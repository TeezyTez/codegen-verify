# 从状态记账到证据决策：机制实验与创新边界

日期：2026-10-09。承接[批判性审核](CRITICAL_RESEARCH_REVIEW_2026_10_09.md)。本轮执行了 **66 次真实 Dafny 验证，0 次被测模型请求**：第一阶段 30 个源码变体各验证两次，共 60 次；随后具体反例证书 4 次、证书补充断言 2 次。后两个阶段是明确的事后诊断，失败全部保留。没有修改生产代码、旧协议、旧候选或历史成绩。

## 1. 研究方向现在应当怎样表述

值得继续检验的候选问题是：**在固定规约和有限预算下，让 agent 区分“已经证明了什么、证明依赖什么、仍不知道什么”，并按需获取额外证据，能否减少错误修复决策？**

这比“把义务状态放入提示”更具体，也更容易被反证。主要对象是修复决策的可靠性和成本：何时只改证明，何时有证据需要改实现，何时保留一个局部证明，何时必须重新验证，何时再花一次验证值得。最终验收仍要求完整 Dafny 通过，所有诊断和试探均计入资源消耗。

**尚未发现足以宣称首次的新算法。** 本轮得到的是候选贡献的可检验边界和可复现机制证据，不是方法优越性的模型实验。新颖性不能靠换状态名称、堆叠模块或把已知验证技术搬入 agent 获得。

## 3. 四项发现和一个阴性结果

### 发现一：相同的完整解析诊断，不代表相同的故障原因

Count 有两种计算主体：每次加 1 的正确实现，与每次加 2 的错误实现。两者都缺少所需循环不变量时，解析后的完整诊断相同：同一位置、同一后置条件、同一错误消息。Copy 中正常复制和每个元素加 1 也得到同样现象。

| 实现与证明状态 | Count | Copy |
|---|---|---|
| 正确计算主体，缺提示 | 后置条件未证明 | 后置条件未证明 |
| 错误计算主体，缺提示 | 完全相同的解析诊断 | 完全相同的解析诊断 |
| 正确计算主体，补提示 | 完整验证通过 | 完整验证通过 |
| 错误计算主体，补同一提示 | 不变量保持失败 | 不变量保持失败 |

每格重复两次，结果一致。这里相同的是诊断，**并非模型可见的完整输入**：代码不同，模型仍可能自行推理出原因。不能据此证明 raw-feedback baseline 无法修复，也不能声称状态摘要加入了新的信息。

错误实现有具体反例：Count 输入 1 返回 2；Copy 输入 `[0]` 返回 `[1]`。为避免把验证失败误当语义反例，另用独立诊断程序形式化验证这些具体输出违反原要求。Count 证书两次通过；Copy 的首版证书两次未证明，追加三个关于长度和第 0 个元素的真实断言后两次通过。原失败证书全部保留，不能将其记为一次成功。

诊断程序用具体输入和否定原输出要求的独立契约，它们**不是原任务的候选答案**，绝不通过更改原契约获得实验成功。相关文件：[证书阶段](../logs/evidence-semantics-probe-20261009/witnesses/plan.json)、[补证阶段](../logs/evidence-semantics-probe-20261009/witness_anchor/plan.json)。

意义：只靠错误类别选择动作，必然存在原因未确定的情形。一个成功的、保持计算主体的证明补丁可以提供强证据；一个失败的证明补丁通常不能证明实现错误。后者需要真实可检查的反例或继续保留不确定性。

### 发现二：目标错误消失，可能只是把证明负担搬到了别处

两个错误实现补上不变量后，后置条件错误都消失，但不变量不能维持，完整验证仍失败。这是“诊断迁移”，并不表示原语义问题已解决。前述具体反例又证实了错误实现确实有错误。

当前引擎没有因此误收答案：完整验证门槛仍然正确。需要防范的是未来调度器把“目标诊断 ID 不见了”“这个后置条件不再报错”当作修复收益，而对新引入、尚未证明的不变量义务不作追踪。错误数也没有充分表达进度。

候选研究价值：能否跟踪一次修复增加、替换或转移了哪些证明责任，使动作评价依据最终目标及其新依赖，而不只依据消失的报错。此思想与已有按动作验收重叠，必须做直接对照。

### 发现三：局部验证通过与依赖全部成立是两层证据

当 `Increment` 的实现错误时，调用它的 `Twice` 和再调用 `Twice` 的 `Client` 仍分别通过局部 correctness 批次；当 `Twice` 错误时，`Client` 同样局部通过。搜索案例中，`LowerBound` 失败，调用它的 `Locate` 可以通过。

第一阶段共有 **4 个不同的“源码版本—方法”组合**满足“本方法局部通过，但已知调用依赖未闭合”；两次重放均复现。这里使用人工明确给出的无环调用图，未自动提取完整证明依赖。

这是正常的模块化验证语义：调用者使用被调用者的契约，而不是再次证明其实现。本项目当前全文件验收没有漏洞；`M:Locate=DISCHARGED` 可以正确表示局部批次通过，但不能脱离依赖解释成完整程序已正确。[Dafny 官方教程](https://dafny.org/dafny/OnlineTutorial/guide)

对生成修复的意义：保留局部证明、定位未闭合依赖可能节约无效改动；但不得把局部成功当成全局成功。应区分证据作用域，而非简单把所有状态都改成“已证/未证”。如果只做缓存或增量验证，这已有成熟先例，不是本项目创新。[Fine-grained Caching of Verification Results](https://www.microsoft.com/en-us/research/publication/fine-grained-caching-verification-results/)

### 发现四：同一类动作的收益取决于当前证明上下文

已暴露的 PrefixMaxima 案例再次复现：A1 加一条见证断言后通过；B3 删除辅助循环后通过；A2 原本通过，删除辅助循环后反而失败。不能将“多加证明”或“尽量删证明”写成普遍策略。

这是已知开发案例的复验，不是新的独立泛化证据。加、删本身已有 DafnyPro 等工作覆盖；价值应来自动作适用条件判断以及判断所需成本，而不是动作名单。

这些辅助循环并非本框架中的 ghost 循环，删除它们还会改变运行时代价；因此不能将该对照直接算成“固定可执行主体的纯注解修复”。本轮只记录其源码局部效果，后续分轨必须明确编辑边界。

### 阴性结果：本轮没有发现空行导致目标选择变化

8 个空行变体、16 次检查全部仍选 R3。该组映射后的诊断位置为 `unknown`，空行没有改变选择键。原选择规则仍是哈希消歧，不能赋予其语义能力；但也不能声称本轮证明它对排版不稳定。其他重命名、义务重排或诊断类型不在本轮结论内。

## 4. 现有状态机现在能否观测到回退

对已保存的真实结果进行了一条**事后人工排序的状态重放**：`search_10 → search_11 → search_01 → search_00`。这条序列先让 Locate 局部通过，再把它改坏，随后修复两个方法。现有 `EvidenceState` 记录了 1 次 `proof_regressions`、0 次 `lost_observability`。

这表明原状态机能记录真实方法批次回退；此前零回退主要因为样本未触发。它没有证明任何策略避免了回退。这次重放没有新增模型或验证调用，也不是自主 agent 轨迹。[重放工件](../logs/evidence-semantics-probe-20261009/authored_state_replay.json)

## 5. 新颖性排除：哪些东西不能再包装成创新

| 候选主张 | 核查判断 | 后续处理 |
|---|---|---|
| 错误驱动动作库、历史驱动规划 | SkillForge、VeruSAGE 等已有 | 必须作为强对照 |
| 加断言、删不变量、裁剪证明 | DafnyPro 等已有 | 作为共享动作与廉价基线 |
| 使用反例诊断证明失败 | ExVerus 已直接研究 | 不能把主动诊断换名后称首次 |
| 依据调用关系保留证明、减少复验 | 经典模块化验证与增量缓存已有 | 复用，不作为核心算法贡献 |
| 把失败经验存成指导 | 已有反思/经验方法及近期证据关联指导工作 | 检验选择和适用条件，而不是仅增加记忆 |
| 预算内选择何时获取证据，并追踪诊断迁移与条件性证明 | 当前可检验的组合假设 | 需要明确决策规则、消融和外部任务验证；尚未建立新颖性 |

ExVerus 指出后端错误粗糙且含糊，并通过可验证的反例指导修复；其反例验证主要覆盖循环不变量，对一些断言失败并无同样保证。这是我们必须面对的近邻，而不是可忽略的旁支。[ExVerus 原文 §3、§5](https://arxiv.org/html/2603.25810v2)

Dafny 故障定位工作把故障范围明确限定为实现错误，研究多反例定位。我们的混合任务还包含计算实现正确而证明不足的样本，因此不能直接采用“验证失败=实现故障”的研究前提；这属于任务设置差别，不是对其限定研究范围的反驳。[Dafny fault localization，2026-08](https://arxiv.org/html/2608.05399v1)

最新核查到的《From Verification Failures to Reusable Guidance for Coding Agents》于 2026-10-07 更新 v3：其完整规则与等长通用建议对照得到混合效果。这进一步说明，把正确经验加入上下文未必有效，选择条件与资源开销需要独立验证。其 K 框架、规约构造与审计设置和本项目不同，不直接移植其分数。[v3 原文](https://arxiv.org/html/2609.39022v3)

## 6. 候选算法差异：把“证据不够”变成可以执行的决策

以下是拟议算法，不是已经完成的生产实现：

1. 为观察记录源码版本、验证器版本、目标性质、证明作用域及所依赖的契约。区分局部证明、依赖闭合、真实反例、未确定；保留失败证据，不用模型自述填补缺口。
2. 面对一个错误，允许多个原因并存，例如“计算错误”“注解不足”“注解自身错误”“资源不足”。仅凭验证失败不能排除其余原因。
3. 在直接修复与有限诊断之间作选择。诊断可以是保持实现的证明补丁、具体反例检查、或合法的证明删减试验；需要预先定义合法边界，并把全部额外调用计入预算。
4. 按结果更新证据。成功仅支持其实际验证范围；失败或超时通常保持未确定。原错误消失但新义务未完成时，记录责任转移，而不把目标直接记为完成。
5. 基于证据选择局部证明修改、实现修改或重生成；最终仍回到完整固定规约验证。

真正待研究的是第 3 步的**证据获取策略**和第 4 步的**证据解释规则**是否带来净收益。不能把我在开发案例上手工挑出的有效探针当作策略的自动能力。不能预设每个错误都应该先探针；简单任务可能只增加开销。

本轮的实证边界：发现了诊断含糊、责任迁移、局部证明条件性三种实际现象；没有证明显式建模这些现象能提高模型修复率。

## 7. 下一轮最有价值的实验

### 7.1 先验证“怎样呈现同一证据”，再验证“何时获取证据”

第一步使用固定、共同失败快照。原始组获得完整源码、诊断、方法批次和历史；处理组获得相同信息，以及明确作用域的结构化证据。目标选择和允许动作保持一致。这个实验检验组织与解释收益，不能把额外提示长度或手工解题建议混入处理组。

第二步让所有组拥有相同合法诊断和修复动作，比较：强通用修复代理、固定错误类型路由、总是先诊断的策略、按证据不足程度选择诊断的策略。不能只给新方法探针或更大的补丁池。另做相同探针结果的原始文本与结构化证据对照，以区分信息增量与组织增量。

当前 A/B/C/随机目标单步对照仍可作为旧算法诊断，但优先价值低于上述问题：哈希同级选择本来就缺少预期优势，重复证明其无优势不能产生强研究贡献。

### 7.2 题目必须包含能区分行为的对子

- 同一规约下，正确计算但证明不足，与计算确有错误的失败起点；具体错误应有独立可检查反例，不能凭未通过给标签。
- 局部方法已经通过，但依赖尚未闭合；修复改变依赖实现与改变依赖契约要区分。本项目主轨继续冻结契约，契约变化只可另设证据失效机制探针。
- 新增证明注解后报错转移的例子；只测初始错误消失会产生错误奖励。
- 同一动作在不同证明上下文中的正、负效果。不能只保留删减有利的样本。
- 真实模型失败作为主评估来源；本轮人工变体仅用于开发和机制检查。

先按基础算法/项目分簇，再划分开发和留出。Count/Copy/PrefixMaxima 及其所有变体已经暴露，不能进入确认集。建议先以约 20–30 个独立开发任务测可行性与成本；数量不是统计功效保证。外部数据准入需先解决本框架 proof 语法支持与契约质量审计。

### 7.3 预算、主指标与失败标准

沿用小预算思想，示例上限为每个起点 3 次模型响应、4 次新的 Dafny 调用；探针、失败候选和最终重验均占用额度。共同起点的生成和初次验证另列一次性数据成本。token、验证资源、全部失败成本另报；不能把相同调用上限称为相同推理计算量。

主指标仍为预算内完整验证成功率，以独立题/算法簇配对估计。机制指标是：缺乏反例时错误宣称“实现有错”的次数、把诊断消失误判为完成的次数、局部证明与全局通过混淆的次数，以及这些决策造成的额外实现改动/验证消耗。模型若不输出诊断结论，不能从隐藏思考推测；应使用明示决策字段或只评价可见动作。

若加入状态只改善解释文字却不改善动作、成功率或成本，就不支持 agent 方法贡献。若按需诊断没有优于相同预算的强自主代理或固定诊断顺序，应报告无额外收益；若仅特定混合错误类别有收益，限定研究范围。不能为了出现正结果扩大样本或调整主指标。

## 8. 研究意义的判断

这条方向的实际意义在于：**减少“验证器说不知道，agent 就盲目改代码”的浪费，让生成与修复围绕可检查的证据进行。** 其价值可以表现为相同预算下更多通过、相同通过率下更少验证/模型消耗、或更少不必要的实现重写。最终验收的可靠性仍主要来自冻结规约与验证器，不应归功于账本本身。

本轮已排除把动作库、缓存或状态名当创新的路线，并补齐了此前未触发的机制案例。接下来要寻找的是这些证据语义在模型决策中的净收益，而不是继续为原 A/B/C 排名寻找解释。
