# 短论文方向证据核查（2026-10-05）

目标：尽快完成可信的短论文/workshop 可投稿初稿。本文为定向一手资料核查，不是穷尽综述，也不保证新颖性或录用。事实、建议及未验证部分分别说明；没有运行付费模型或修改实验代码。

## 结论与建议

**建议：做固定公开 Dafny 契约下的验证反馈诊断研究，定位为跨领域复现与经验分析。** 暂缓自然语言/清单/JSON 三表示、自动规约生成、Typed IR 编译器和新 Agent 架构。原因是当前框架已有冻结契约、独立采样、迭代反馈和轨迹记录；研究诊断信息损失只需较窄改动，而三表示研究还需要等价性审查和内容控制。

不能再把“模型重复错误候选”“修复未必优于重采样”“明确要求代码改变”作为首次发现。2024—2026 年已有直接证据，2026-10-01 又出现非常接近的变化/停滞研究。最值得测试的问题是：**固定且公开相同形式契约时，压缩后的 Dafny 诊断与完整诊断相较，会怎样改变证明注释修复、可执行逻辑修复和重复失败的分布及成本？** 这是建议的细分问题，不是已证实的研究空白。

## 六项关键一手证据

1. **同预算修复比较已有经典工作。** Olausson 等《Is Self-Repair a Silver Bullet for Code Generation?》（ICLR 2024）研究 Code Llama、GPT-3.5、GPT-4 在 HumanEval/APPS 的自修复；计入修复成本后，收益随任务而变，有时不存在。我们的同预算独立采样是必要控制，不能单独当作创新。[论文](https://arxiv.org/abs/2306.09896)；[会议原文](https://openreview.net/pdf?id=y0GJXRungR)。

2. **近重复/anchoring 已被直接研究。** 《Try Again, Don’t Look Back》（arXiv v1，2026-07-28）§3 对比 blind resampling、旧代码加失败通知、真实执行反馈、反思反馈；§5 测代码相似度，报告看见自身旧代码时近重复更常见。§3 还说明 greedy 解码曾造成重复采样无变化的测量问题。该文是预印本，不能把其结论推广到所有模型或形式证明。[原文 §3、§5、§9](https://arxiv.org/html/2607.26117v1)。

3. **最新工作已覆盖“要求修改”和诊断粒度。** Jindae Kim《Inducing Code Change in LLM Self-Debugging: Effects on Program Repair》（AI，2026-10-01）比较失败状态、首个失败、所有失败，并区分文本/AST 未变及改变后仍失败，考察最多四轮修复。对象为六模型生成的 9,790 个 Python 程序。出版商搜索页面返回摘要、方法和结果；直接打开页面失败，未下载复现包。这里的潜在区别是 Dafny 中仅修改证明注释可能已经有意义，不能照搬“可执行行为必须改变”的提示或指标。[出版商原文](https://www.mdpi.com/2673-2688/7/10/392)；[版本日期](https://www.mdpi.com/2673-2688/7/10/392/notes)。

4. **Vericoding 已做固定规格到实现与证明的循环。** 《A benchmark for vericoding》（2025-09-26 v1）§4/Fig.3 已展示填充代码块、检查 bypass、完整验证、把错误返回模型的循环；常规任务给五次尝试。摘要的 Dafny 82% 是多模型成功集合，不能误写成单模型成绩。我们应贡献受控比较和诊断分析，不重复宣传这个循环本身。[原文](https://arxiv.org/html/2509.22908v1)。

5. **DafnyBench 的原任务主要是证明补全。** DafnyBench 从现有程序中移除验证提示，评估 LLM 补足提示以通过验证，也已经比较错误反馈重试。直接将其结果与删掉完整方法体的生成任务混合不成立；删方法体会形成新的派生任务，需要公开转换和排除清单。[作者论文](https://arxiv.org/abs/2406.08467)；[作者仓库](https://github.com/ChloeL19/DafnyBench)。

6. **MBPP-DFY 可备用，但不是直接可用的冻结契约生成集。** FSE 2024 的 Dafny synthesis 仓库提供 153 个已验证实现，其中 50 个人工实现、103 个 GPT-4 实现；另有 228 题的描述/签名/样例版本。需要剥离实现、保留辅助定义、审查契约强度并复验工具版本。[作者仓库和数据说明](https://github.com/Mondego/dafny-synthesis)；[论文](https://arxiv.org/abs/2402.00247)。

## 数据集适配判断

优先审计 [Vericoding benchmark](https://github.com/Beneficial-AI-Foundation/vericoding-benchmark) 的 Dafny 子集。官方仓库把 preamble/spec/code/postamble 分开并提供 JSONL，比重新解析完整 Dafny 文件更贴近当前方法体生成器；但 12,504 是多语言全量，不是可直接运行的 Dafny 任务数。仓库明确保留不编译、规约有问题的任务，不能全部当可靠验收标准。

适配前先做不调用模型的准入审计：固定源提交；记录每个排除原因；检查槽位数、辅助声明、允许语法、完整参考验证和 bypass；按来源去重/分组，避免同源变体跨开发与测试。当前 runner 对多少任务能无损适配仍未知，不能承诺几千题或低成本完成。若优先子集适配不顺，MBPP-DFY 是备选；DafnyBench 原生 proof-completion 是另一种任务，必须单独报告。

## 最小可信实验（建议，尚未实施）

所有组公开完全相同的冻结形式契约、签名、辅助定义和输出协议；只改变后续上下文。现有隐藏契约运行作为开发观察单独保存，不并入新主实验。

| 条件 | 失败后的输入 | 用途 |
|---|---|---|
| Independent sampling | 原始公开任务，新采样 | 额外尝试的基线 |
| Failure-only | 旧候选 + 失败状态 | 测旧候选自条件化 |
| Controlled diagnostics | 旧候选 + 当前压缩诊断 | 评估现有反馈通道 |
| Full diagnostics | 旧候选 + 完整 Dafny 诊断 | 测压缩造成的信息差异 |

同一 task/model/repeat 的初始候选共享，后续随机流分开；所有组设置一致采样参数、尝试上限和验证上限。等调用数不等 Token，必须另报告 tokens/time/verification cost 和质量成本曲线。首轮正确任务无需继续但保留在整体分母；修复条件成功率另以首轮失败为分母。不要把多个重复运行当作独立任务。

主要结果：预算内验证成功率、配对差值与按任务聚类置信区间。机制结果：完全重复、仅证明注释变化、可执行逻辑变化、混合变化以及相应成功率；语法/名称/类型错误与证明错误分层。文本或 AST 差异不等于语义差异，自动分类必须抽样人工复核。完整诊断的作用可能只来自修复粗分类丢失的语法错误，不能事后泛化为“形式推理增强”。

30/40 题只能作为适配与试验起点，不代表统计充分。先以开发集测成本和首轮失败分布，再冻结测试集、主比较和样本量策略；不得看到测试结果后追加任务直到显著。若效果接近零或不稳定，报告不确定性和适用范围，依然可以形成复现/诊断短论文。

## 落地范围与工程起点

任务固定为公开契约下的方法体生成，不能把 proof completion 混入分母。四组简称 I（独立）、S（旧代码加失败状态）、C（旧代码加冻结的 `controlled_v1`）、F（旧代码加完整诊断）。每个逻辑运行上限 K=4 次模型请求，包括首轮；若共享首轮候选，分别记录实际调用成本与各策略的归属成本，避免低估任一策略成本。

工程起点可设为 30 个未用于调参的外部适配测试任务 × 2 模型 × 3 重复 × 4 组，即 720 个逻辑运行、未共享时最多 2,880 次请求；共享和提前退出会减少实际请求。现有 8 个任务仅用作开发。这个数量不是统计充分性保证，应先用开发 pilot 估计成本、效应可检测范围和区间精度，再冻结主实验规则。

编辑标签采用 `no-change / proof-only / exec-change / mixed / invalid`，将无法可靠分类的候选保留为未知并人工抽查。验证失败可能是证明不足、超时或工具错误，不能直接记为程序语义错误。若工具修复和数据准入顺利，可把 7–10 个工作日作为实验与短论文初稿的工作计划；它不代表录用时间，也不能绕过数据质量和证据不足的停机判断。
