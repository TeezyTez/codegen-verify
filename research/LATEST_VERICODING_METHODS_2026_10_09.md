# 固定可信规约下的验证代码生成：最近邻核查（2026-10-09）

检索与核查日期：2026-10-09。范围：可信 Dafny 规约固定后生成实现及证明、验证反馈修复、义务/证明状态到目标与动作的调度、联合规划、最小注解修复。下文区分论文实际方法、作者报告的结果、以及我们的研究判断；不横比不同基准的成功率。没有运行付费实验或修改代码。

项目现状按本次任务提供的信息：只有 `UNPROVED/UNKNOWN/DISCHARGED/STALE` 状态账本，按状态优先级及哈希 ID 选择 target，把 target 加入提示，最多三轮全方法体生成；尚无动作策略、证明依赖图或受限局部补丁。本文件不把拟议功能写成已有能力。

## 结论

**当前实现更像可审计的反馈循环原型，尚不足以构成强方法新颖性。** 固定规约、验证器反馈、错误定向修复、增删注解、程序证明联合规划均有直接或强相邻工作。尤其应纳入 SkillForge、DafnyPro、VeruSAGE，而不能只拿一次生成或朴素“错误全文回喂”作比较。最近的 MAGS、Djinnlang 也已把冻结规约与 Dafny 证明义务放进完整工具链。[SkillForge](https://arxiv.org/html/2608.29841v1)、[DafnyPro](https://arxiv.org/html/2601.05385v1)、[VeruSAGE](https://arxiv.org/html/2512.18436v2)、[MAGS](https://arxiv.org/html/2609.19391v1)、[Djinnlang](https://arxiv.org/html/2609.23954v1)。

可研究的问题应收窄为：**在固定可信规约与相同预算下，怎样根据跨轮次证据选择“修哪项义务、用什么编辑动作”，并证明其优于错误类型路由、通用强代理和局部修复。** 这目前是待检验假设，不是已建立贡献，更不能写成“首次”。

## 六项方法深读

### 1. SkillForge：错误分类到动作选择的直接最近邻

- **身份与状态**：Yanming Liu 等，*SkillForge: Compositional Skill Synthesis with Verification-in-the-Loop for Generating Formally Verified Dafny Programs*；2026-08-30 v1，核查时无更新版。arXiv comments 自报 EMNLP 2026 accepted；本次未在正式会议名单/ACL Anthology 独立确认，故不把正式录用状态视为已双重核实。[元数据](https://arxiv.org/abs/2608.29841)
- **方法**：六个技能；正则加 LLM 回退输出类别、位置、建议；将 invariant/spec/body/type 错误分别路由到不变量生成、规约加强、局部修复、体重生成。保留错误与历史，支持停滞重启、回滚；局部修复约束最小改动。它允许补充/加强规约，故不完全等同本项目固定规约任务。[§3、附录 B](https://arxiv.org/html/2608.29841v1)
- **评估与局限**：178 个自建样例、5 轮；报告诊断随机路由消融明显变差。但随机路由是弱对照；“postcondition失败→spec_gap”并不能鉴别实现错误、证明缺失和规约不足。论文把验证器称为 perfect oracle、将路由称为 optimal，缺少相应最优性论证；其基准适配不能当成原系统公平复现。未定位可核查的作者实现仓库。[§4–5、附录 B/H](https://arxiv.org/html/2608.29841v1)
- **判断**：不能再声称“验证错误驱动专门动作”是新概念；固定规约只是必要任务边界，须证明更细证据带来的额外收益。

### 2. DafnyPro：删除多余不变量已经是现成方法

- **身份与状态**：Debangshu Banerjee、Olivier Bouissou、Stefan Zetzsche；2026-01-08 v1，核查时无更新版；POPL 同期 Dafny 2026 workshop 官方日程列 2026-01-11 报告，不能写成 POPL 主会论文。[arXiv](https://arxiv.org/abs/2601.05385)、[官方日程](https://popl26.sigplan.org/details/dafny-2026-papers/12/DafnyPro-LLM-Assisted-Automated-Verification-for-Dafny-Programs)
- **方法**：给定实现及规约，生成证明注解；用 Dafny parser 检查去掉注解后基础代码不变；贪心删除验证器报告的非归纳不变量，再验后置条件，失败则恢复；提供八类人工编写、问题无关的证明提示。[§3–4](https://arxiv.org/html/2601.05385v1)
- **评估与局限**：四个注解补全基准、两种 Claude、10 次尝试，报告剪枝与提示各自增益；还修复了 DafnyBench 中 70 个去注解后无法编译的输入，因此复现必须锁定数据版本。剪枝针对阻碍验证的非归纳子句，不保证注解总数或编辑成本全局最小，也不选择实现结构。[§4.2](https://arxiv.org/html/2601.05385v1)
- **判断**：单独增加 `delete_invariant` 或验证后清理，不足以形成新方法；须比较可执行的贪心剪枝基线，并定义“最小”到底指补丁、注解数还是验证成本。

### 3. AxDafny：固定规约下的程序与证明反馈生成已直接覆盖

- **身份与状态**：Benjamin Breen、Austin Letson、Borja Requena Pozo、Leopoldo Sarra；2026-06-30 v1，核查时仍仅该版；未核实正式会议录用。[元数据](https://arxiv.org/abs/2606.32007)
- **方法**：proposer 返回完整文件；保留前一轮及压缩记忆；静态规约/绕过检查、Dafny 诊断和 LLM reviewer 联合验收；可加入反例反馈。范围同时包含固定代码补注解和给定规约生成实现/证明。[§3](https://arxiv.org/html/2606.32007v1)
- **评估与局限**：DafnyBench 加 250 题 LCB-Pro-Dafny、最多20轮；新基准主要对照一次生成，因此不能把结果完全归因于某种调度机制。规约检查先保留原 requires/ensures 文本子集，再由 reviewer 防语义作弊；这不等价于 AST 级完全冻结。论文另区分验证通过与编译后运行的资源限制。[§3–5](https://arxiv.org/html/2606.32007v1)
- **判断**：本项目“target提示＋三轮整体生成”接近其简化反馈循环；目前账本没有展示出可区别的修复决策。

### 4. P³：程序证明联合规划已明确提出，但实验证据限于 Lean

- **身份与状态**：Zenan Li 等，*Joint Program-and-Proof Planning for Verified Code Generation*；2026-08-10 v1，核查时无更新版；未核实正式会议录用。[元数据](https://arxiv.org/abs/2608.09277)
- **方法**：先联合选择程序分解、表示、终止量、桥接谓词、引理与证明结构，再按冻结计划展开。局部 elaboration 错误原地修；需要未计划的算法、不变量或结构性引理时重新规划。[§3](https://arxiv.org/html/2608.09277v1)
- **评估与局限**：三个 Lean 基准、四个模型，对比普通代理、先程序后证明，并有仅实现规划消融。论文明确承认：每配置一次运行、无任务内随机方差估计；Dafny/Verus 迁移尚未实验。效率优势的主要分析还限定在高成本子集。[§5、附录 C/J/L](https://arxiv.org/html/2608.09277v1)
- **判断**：本项目不能仅凭“先列义务/计划”主张联合规划新颖性；可检验的是这种机制在 SMT 诊断不确定时，何时应局部修复、何时应换实现结构。

### 5. VeruSAGE：动作规划、验收规则与历史状态的强相邻最近邻

- **身份与状态**：Chenyuan Yang 等；2025-12-20 v1，最新核实为 2026-04-15 v2；本次未核实正式会议版本。[元数据](https://arxiv.org/abs/2512.18436)
- **方法**：固定 Rust/Verus 实现与规约补证明。候选选择器可回退；planner 结合错误、上下文和历史选 action；静态分析过滤/优先可用动作；输出局部 diff。验收依动作而异：分情况证明允许增加子目标，但须消除原目标且不影响块外；专门求解动作要求错误减少。[§4.2](https://arxiv.org/html/2512.18436v2)
- **评估与局限**：849 个系统证明任务，四个模型；强 Sonnet 的通用代理模式反而优于细粒度手控模式。论文指出硬编码选择可能误判候选潜力，过小步骤也拖慢强模型；它是固定实现证明任务，不能直接证明实现生成效果。[§5.6](https://arxiv.org/html/2512.18436v2)
- **源码佐证**：作者仓库列 35 个动作、按目标/错误降低/不破坏已证部分验收；这是 2026-10-09 读取的 main 文档，未锁定提交，不能据此推断全部动作在论文首次版本已存在。[动作目录](https://github.com/microsoft/verus-proof-synthesis/blob/main/verusage/agents/actions/README.md)
- **判断**：调度必须对比强通用代理；不能预设细粒度必胜，也不能仅用错误总数作进步函数。

### 6. MAGS：2026年9月的冻结规约＋证明规划/修复直接近邻

- **身份与状态**：Albert Wu 等；2026-09-16 v1，未核实正式会议录用。[元数据](https://arxiv.org/abs/2609.19391)
- **方法**：领域语义经审核后冻结；生成多种证明策略和轻量注解草图，先让验证器试探，再并行展开。先允许注解修改，必要时开放实现修复；禁止改冻结语义及验证绕过，并积累成功策略。[§3](https://arxiv.org/html/2609.19391v1)
- **评估与局限**：CUDA/终端/机器人共220任务，25次代理调用预算。形式通过与外部安全、功能保持分别衡量；终端的外部安全失败、机器人最初“安全但不完成任务”的结果，显示冻结不完整语义仍不等于原意。单样例开销很大，成本排除一次性语义构建；没有隔离“义务调度”的因果消融。[§4](https://arxiv.org/html/2609.19391v1)
- **判断**：先证明后实现修复、先试探草图再展开也已被直接使用；我们的差异若存在，应是预算内决策及证据机制。

## 对“状态账本”增量的批判性判断

这里是基于上述方法与当前项目描述的推断，不是论文原文结论。

| 拟议表述 | 判断 | 缺少什么证据 |
|---|---|---|
| “规约不可改，直到验证通过” | 基础实验边界；AxDafny、Djinnlang、MAGS已有不同实现 | AST/语义保护的覆盖与可复现通过判据；不能只靠提示 |
| “根据未证义务选择 target” | 有用工程结构，但目前状态优先级＋哈希排序缺语义决策 | 同预算对比 source-order、随机、最早错误、全量反馈；证明选择而非提示长度在起作用 |
| “按失败类别选择修复动作” | SkillForge直接覆盖；VeruSAGE覆盖更丰富历史/上下文规划 | 错误原因混淆时的鉴别能力、动作选择校准及收益 |
| “已证部分不回退” | 有近邻验收机制；简单单调规则可能错杀必要分解 | 跨版本义务身份匹配、失效规则，以及必要临时回退的处理 |
| “删除多余证明” | DafnyPro已做针对性剪枝 | 哪种最小性，是否安全保持原规约，何时删比增/改更优 |
| “程序与证明联合规划” | P³明确提出；MAGS已有证明策略试探 | Dafny下如何触发重规划、相较固定计划/只规划实现的因果增益 |

状态名称是记录格式，只有它实际改变行动并改善结果才成为方法。`UNKNOWN` 应保留“诊断不足/超时”的不确定性，不能自动视为实现错误；`STALE` 应指当前版本缺乏有效证据，不能把旧成功当当前成功。整份源码哈希可以标识版本，却不能独自建立义务的跨版本对应关系；依赖诊断文本和位置的标识也可能在无语义变化的编辑后改变。未来若建立义务谱系，应先在受控编辑上测量匹配与失效判断的准确性，不能把现有哈希记账直接称为谱系追踪。

## 尚可检验的研究假设与最低对照

1. **证据驱动的目标＋动作选择优于单独错误类型路由。** 冻结规约，显式区分不变量入口失败、保持失败、后置条件依赖不足、终止与资源超时；动作最少含添/改/删注解、引理分解、局部实现修改和重生成。对照应保持相同模型、提示信息、总 token、验证器时间，比较朴素反馈、SkillForge风格路由、强通用代理、带账本的实际策略。只加 target 的版本是必要消融。
2. **跨轮义务谱系能减少修复回归，但必须允许有根据的义务分裂。** 用受控局部编辑和等价重排评估身份匹配的准确率；记录旧义务→新义务一对多关系。对比分数不应只有“剩余错误数”，还应包括最终验证、回归次数、重复尝试及验证开销。若依赖仅来自已完成证明的 unsat core，需明确它不是完整因果依赖。
3. **先验证删减候选能节约预算，但优于贪心剪枝才有价值。** 固定原始规约/允许动作，比较“始终添加”、DafnyPro式非归纳子句删除、一般删除试探与策略选择；同时报告补丁大小、注解数、验证时间和求解稳定性，防止只把证明变短当质量提高。预算必须包含删减所增加的验证器调用。
4. **停滞时联合重规划比继续同类局部修复更有效。** 记录什么证据触发从 proof edit 切到 code edit/重规划；对照固定计划、实现规划、联合计划及无计划强代理。P³迁移至Dafny可以是实证问题，但不能仅以更换语言包装新颖性。

优先次序建议：先把同预算的通用代理、错误类型路由和贪心剪枝做成可复现基线，再选一个假设；目前不要同时承诺证明依赖图、联合规划、最小证明和学习策略四条路线。三轮全方法体生成主要只能检验提示干预，不足以评价长程修复决策。
