# 四组恢复实验：差异、反事实验证与新发现

本分析针对 [四组恢复实验](FILE_HANDOFF_RECOVERY_RESULTS_2026_10_07.md)，不改变其成绩：A 两轮通过、B 三轮未通过、C 三轮通过、D 一轮通过。只有一个开发题、每组一次，没有策略优劣的可靠估计。

本轮额外执行 **23 次真实 Dafny 验证，0 次模型请求**。所有改动仅存在于 `logs/recovery-mechanism-analysis-20261007/` 的副本中，契约与工具链不变。13 次第一阶段对照后，按观察结果增加 5 次辅助循环消融、5 次最小断言定位及复现；这是明确的事后、自适应机制诊断，不是新增模型实验，不进入原成功率或预算分母。所有成功和失败均保留。

## 1. 最大的新发现：存在更小的修复，而且添加证明代码可能降低可验证性

| 原候选 | 只改变什么 | 结果 | 可以支持的局部结论 |
|---|---|---|---|
| A 第 1 轮：失败 | 输出追加前加入 `assert exists j :: 0 <= j <= i && m == s[j];` | 通过；独立复验仍通过 | 原计算主体可以满足契约，不必像 A 第 2 轮那样增加来源序列及辅助循环 |
| B 第 3 轮：失败 | 删除末尾第二个、只用于证明存在性的循环 | 通过；独立复验仍通过 | 在这份源码中，辅助证明循环构成了验证障碍；保留主计算循环即可证成 |
| C 第 3 轮：通过 | 删除最后三条量化断言，保留此前非空分支内的三个断言 | 仍通过 | 不能把本轮成功归因于最后三条量化断言 |
| C 第 2/3 轮共同主循环：失败 | 末尾仅补 `if |s| > 0 { assert p[0] == s[0]; }` | 通过 | 一个具体元素的事实已足以在这个验证上下文中完成证明 |

C 的另外两个单断言版本也通过：非空时断言 `witnesses[0] == 0`，或断言 `0 <= witnesses[0] <= 0`。这些只是本题中充分的改动，不能理解为“证明第 0 个元素就证明了所有元素”；全称性质仍由 Dafny 对完整方法验证，主循环中的全称不变量继续存在。

不能直接用新增行数解释修复贡献。A 的实际第二轮采用了更复杂的有效路径，但存在仅增一条断言的有效修复；B 已有正确的来源序列，却被新增的证明循环阻碍；C 的成功尾部含有可删的证明文字。它们共同指向一个可研究的问题：**如何选择足够而精简的证明修复动作。**

这些结果支持“验证对证明上下文和表达方式敏感”。尚未检查求解器的量词实例化追踪或中间验证条件，不能声称已定位到具体 trigger 或循环编码规则。

## 2. 一些看起来合理的解释被对照否定

全部第一阶段原样对照复现了原结果，随后发现：

| 假说/改动 | 结果 | 解释边界 |
|---|---|---|
| B3 改成 A2 的固定全域＋析取式存在性不变量 | 仍失败 | 这一项表达式形状不足以修复 B3 |
| A2 反向改成 B3 的前缀区间不变量 | 仍通过 | 不能用这两种不变量写法单独解释 A/B 胜负 |
| B2 只把变量 `witness` 改名为 `idx` | 从解析错误变成验证未通过 | 命名错误消耗了一轮，但修好它仍未完成证明 |
| D1 删除与 A1 新增内容相同的直接存在性断言 | 仍通过 | 同一断言在不同证明上下文中的作用不同 |
| C3 删除两处 `p[k] == p[k]` | 仍通过 | 恒等式不是该成功版本的必要条件 |
| A2 删除第二个证明循环 | 失败 | “删除辅助循环”不是普适修复规则 |
| C2 删除第二个证明循环 | 失败 | C 的主循环还需要额外提示；不能把 C 的成功仅归于删除循环 |

因此不应事后编一个统一故事，如“来源序列解决了问题”“析取不变量更好”“显式恒等式触发了证明”。这里得到的是源码局部的可复现证据及其边界。

## 3. 本次没有激活证据状态最重要的能力

审计 B/C 的全部六份模型输入，**成功前 DISCHARGED 义务数均为 0**。

目前 `EvidenceState.observe` 只有完整验证成功时才把各后置条件记为 DISCHARGED；失败时，无独立证明证据的条款保持 UNKNOWN，明确关联的失败条款为 UNPROVED。这是保守且正确的记账方式，但在单方法题中存在实验局限：模型从未收到“这部分已有证明、只修剩余部分”的状态。成功后运行立即结束，没有下一轮需要保护这些证明。

因此本题实际检验的是失败状态整理与目标提示，尚未检验已证部分保护、证明回退恢复、跨方法依赖调度。原日志中 `proof_regressions=0` 也不能证明保护机制有效，因为没有成功前可回退的已证义务。

相关实现：`generation/obligations/state.py:55` 起的证据归类；可核查输入摘录：`logs/recovery-mechanism-analysis-20261007/prompt_audit.json`。

## 4. 当前目标选择存在一个重要限制：同级候选按哈希 ID 排序

`select_target` 的实际顺序是：优先语法等基础错误，然后按 UNPROVED/STALE/UNKNOWN 等状态排序，再优先诊断，最后按 ID 字典序确定一个目标。

本题初始 R1、R2、R3 都失败，三个后置条件诊断同级。选中 R3 的最后依据是：

```text
R3 → D:41f885e1c671bb20
R1 → D:807ec1731650a97e
R2 → D:a9f0e3a77a7f9796
```

因此，首次选中 R3 不能解释成系统识别出了最难的性质或依赖瓶颈。当前是确定性消歧，没有根据修复收益、失败原因或依赖关系来裁决同级目标。这不使实验无效，但限定了 C 组所代表的算法。

此外 target 只告诉模型优先处理什么，并未规定应该补充具体见证、调整不变量、删除无效证明循环还是重写实现。上述局部对照恰好表明，**选哪个义务与选什么修复动作是两个不同问题**。

相关实现：`generation/obligations/state.py:96–108`。

## 5. 组间新增信息有限，不能把更多状态等同于更好的指导

A 已获得完整当前代码、历史候选、真实验证输出和关联到 R1/R2/R3 的结构化诊断。B/C 额外提供当前状态汇总，C 再给一个目标；没有给出新的外部证明事实。

首轮 user 文本长度为：A/D 3,426 字符，B 4,500（+31.3%），C 4,646（+35.6%）。这是字符长度，不是 token 或成本比例，也不能证明更长提示导致较差结果。它说明目前新增的主要是状态重排和注意力提示，尚未提供动作级证明指导。

A/D 首轮 SYSTEM/USER 文本哈希相同，但 A 首轮失败、D 首轮成功；D 没有实际进入第二次采样。因此本次不能声称独立重采样策略战胜了反馈修复，只能说一个独立首轮样本更容易验证。服务时间、平台环境和随机性没有被单独分解。

## 对下一阶段设计的影响

1. **用真实模型失败建立共享失败池。** 本次 A1、B3 等可以作为开发级条件修复起点，冻结后让各组修同一份代码和诊断；不要只依赖明显算错的人工起点。它们已经暴露，不能作为独立留出题。
2. **增加动作级消融。** 比较相同证据输入下，只有目标提示与明确动作选择的差别。候选动作至少区分语法修复、补具体见证、调整循环不变量、删除辅助证明代码。新增动作仍须由 Dafny 验证，不能由模型自证。
3. **单独检验目标选择。** 对比现有哈希消歧、随机同级目标以及有依据的选择规则；没有这个消融，就难以解释目标选择的贡献。
4. **补充能观测部分成功的任务。** 在固定协议中加入多个方法、真实调用依赖、某些批次已通过而另一些失败的题；若允许模型随意消除调用关系，应记录其对调度机制可测性的影响。
5. **保留原计划和失败。** 原 96 次矩阵仍未完成；本轮 23 次诊断不补齐它，也不把 B 改记为成功。下一批要在采样前冻结版本、预算与纳入范围。

目前最有依据的研究方向是：将“义务状态”继续推进为“证据支持的修复动作选择”，检验其是否减少无效改动和验证开销。这个方向由局部诊断提出，收益尚待新的受控模型实验检验。
