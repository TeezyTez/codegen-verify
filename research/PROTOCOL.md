# 研究问题与冻结规约修复协议 v1

> 2026-09-13：本协议作为已实现的修复轨道保留。下一阶段主线转到 [固定可信规约代码生成](FIXED_SPEC_GENERATION.md)，
> 不将旧任务、准入条件或回放分数直接改名成生成实验。

## 定位

长期：软件变更时维护实现、形式规约和证明的一致性。
第一篇：固定目标规约、相同资源上限下，显式依赖信息能否改善多函数验证修复的位置/动作选择，
提高全任务成功率、减少回归和验证成本？新颖性与有效性均待检验。

目标对象是一个文件内多个顶层 callable。CSV 每项是 callable 的验证批次，
不是独立逻辑 VC。实际 SMT 依赖尚未提取，不能把词法边称为已证明的依赖。

## 任务与成功条件

`Task`：program.dfy + task.json；元数据含 source_project、split、origin、failure_type、mode、regions。
`proof` 固定实现和所有目标契约，只能修改指定 invariant/assert 区域。
`implementation` 允许指定语句区域及证明区域变化。新引理需要策划者预先提供声明/证明区域；
v1 不开放自由新增声明。需求变更、目标规格演化、真实提交级 bug 不在当前样例范围。

patch 是 region ID 到替换内容的 JSON。框架在可信模板上重建整个程序，
最终从磁盘重新读取、检查不可变区域、再次完整验证。通过必须满足：

- 修改范围合法，未引入假设、额外公理、属性跳过验证、非终止绕过等；
- 最终 Dafny 进程成功，明确报告正数 verified、零 errors，CSV 所有条目 passed；
- 原始报告中存在的批次均仍存在，且未超预算。

验证状态：passed / verification_failed / timeout / unknown / compile_error / tool_error。
超时、未知和缺失日志都不等同证明通过。失败可能来自证明不足、实现错误、规格冲突或工具限制；
本框架不凭错误类别自动断言哪一个成立。形式正确仅相对于给定目标与 Dafny/SMT 可信计算基础。

## 单一候选机制

`build_graph` 提取调用、契约引用、已声明引理引用，并带 `conservative_lexical_approximation` 标签。
报告中的失败位置映射回 callable。调度优先有失败的可编辑区域，再优先未解决依赖较少的区域，
最后以引用它的数量和稳定 ID 排序。完整源文件和完整错误仍向各条件开放；
依赖组额外获得引用图、相关源片段和建议位置，避免把上下文删减与调度同时混淆。

普通语法引用、保守近似边、已证实逻辑边分别命名；本版最后一类始终为空。
共享不可变契约使调用者可能在被调用者失败时通过。因此调度只是可证伪的启发式，
不假定失败沿调用边传播。图构建必须接受同名/嵌套/别名等当前不支持的局限。

## 对照组

| condition | 运行行为 | 额外信息 |
|---|---|---|
| independent | 每轮从原始坏程序独立提出候选，不看前次诊断 | 无 |
| linear | 整文件错误反馈下逐轮修复 | 无图、无显式调度 |
| generic_agent | 模型自主选择 read/patch/verify/stop，保留最近工具轨迹 | 无专用调度 |
| dependency | 线性循环 + 保守依赖图 + 调度建议 | 唯一主要机制 |
| no_dependencies | 保留 failed-first 调度，移除图 | 去依赖消融 |
| no_schedule | 提供相同图，移除建议位置 | 去调度消融 |

所有组工具、合法修改范围、回归回退策略和预算相同。generic_agent 是受控的通用工具循环，
不等同某一商业 coding agent；它目前没有任意 shell 权限或仓库浏览环境。
独立组每轮重置代码和反馈，其固定初始输入不会被按轮改变的诊断污染。
任何方法都不能读取 reference.json/replay.json；replay 适配器读取脚本仅做协议诊断。

默认每次运行：6 模型调用、10 完整验证调用、48,000 token、每次输出最多 2,048 token、180秒。
初始验证、模型自主验证、最终重验全部计数；同一调用失败也消耗次数。
调用前用 UTF-8 字节数+256 开销+输出上限做保守预留，返回后记录供应商用量；
缺失用量保留预留值与 unknown 标记。该估计不是供应商 tokenizer 的形式上界，
供应商超额时记失败并停止，不能宣称绝不越过供应商计费。价格未知写 null，不编造费用。
实际重复运行不是独立采样 pass@k，也不承诺温度或 seed 让供应商确定性复现。

## 任务策划与评估

每项保存 original.dfy、故障版本、reference.json。validate 实际确认原始通过、故障失败、参考通过。
live 运行会在模型客户端构造前自动执行准入；该统一离线策划成本单列，不计入某个方法的修复预算。
真实 bug、人工变异、缺失注释分开；新增 Consumer 必须声明为人工组合。
开发/测试按原始来源项目划分，不能按派生文件随机划分。
实现 source-project 校验和标识符归一化的模板近重复初筛；语义近重复仍需人工审计。
本次样例全部为 dev，尚不存在冻结的独立测试集，不能做确认性效果声明。

主指标是合法修改后完整重验成功率；按模式、来源、失败类型分组。
同时报告 token、价格已知时的成本、时间、验证调用、修改行数、已通过批次的回归。
缺失批次记录 lost_observability，不假称回归或通过。超预算/拒绝/工具失败保留分母。
来源项目聚类 bootstrap 给 source-macro 95% 区间；不足两个项目时返回 null。
配对比较按 task×replicate 配对并报告缺失配对；不混用 task-run 平均差与 source-macro 区间。
当前脚本提供估计和区间，不执行确认性显著性宣称；未来预注册主比较并控制多重比较。
计划任务缺结果单列，不丢弃后只展示成功案例。不同配置/模型的独立 suite 不能直接混合。

## 威胁与决策门槛

1. 构造偏差：小算术题和手工洞位不能代表真实证明修复。先审计公开多函数/共享引理任务。
2. 边界先验：region 限制缩小定位空间；比较是在相同候选位置集合内选位置，不能宣称任意定位。
3. 规格不足：原始验证不证明题意正确。目标意图与可满足性仍需要人工审查。
4. 假依赖：保守图可能主要增加 token。必须保留 no_dependencies/no_schedule 及强 generic 基线。
5. 策略成本：先后调度带来的收益须扣除更多提示 token 和额外验证，不以调用次数相等代替成本相等。
6. 模型污染与版本：公开任务可能进入训练；记录模型快照、来源版本、相似任务和时间。
7. 固定实现模式里不同失败可完全解耦；应测共享辅助证明场景，若仍无稳定瓶颈，停止扩充图算法。

下一阶段先策划 10–20 个公开开发任务，至少三来源、每题2个以上可编辑位置，
区分共享证明依赖和仅调用依赖。冻结任务后，再经付费授权以同一模型每组3次小试。
继续标准：多个来源上定位/动作选择和成本出现一致改善，收益超出无图调度消融。
调整标准：图只增加成本、优势仅来自人工洞位或某一来源、generic 已同样有效。
此时收窄到共享引理上下文选择或错误义务定位研究，不增加 RL/GNN/多 Agent 来掩盖结果。

## 下一次实验的具体顺序

1. 先固定10–20个开发任务：优先公开 proof-repair，至少3来源、每题至少2个合法位置；
   每个任务同时保存出处、上游提交、许可证、参考工件、变异方式及三版本验证。
2. 分开“仅调用关联”和“共享证明辅助项”两层。位置标签由人工审计允许多个有效位置，
   不把 reference patch 的位置视为唯一正确答案，不从 failed 标签自动推断程序 bug。
3. 精读并落地一个同任务公开方法：优先 DafnyBench 反馈循环原始配置，其次 DAISY；
   区域补丁版本与原始整文件版本明确区分，不混报忠实复现和受控改编。
4. 经明确付费授权后，先同一模型同一快照、6条件×3次；记录思考模式、服务端版本、完整用量与价格日期。
   当前 live 接口已完成离线接线，但未验证任何供应商在线行为，不能跳过1–3项直接扩大。
5. 除成功/成本外，根据候选轨迹人工标注第一次有效位置选择、无效位置占比和动作类别；
   当前自动脚本只记录建议/实际区域，不声称已经自动测量“定位准确率”。
6. 开发结论冻结后按来源选新的独立测试集、预注册主比较；先做方差/成本估算再决定样本量。
   不保证固定小样本足够显著，不因某一成功例就扩大预算。
