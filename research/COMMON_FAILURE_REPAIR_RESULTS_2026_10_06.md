# 公共失败起点修复实验：2026-10-06

本轮完成了预定的 8 次真实模型运行，8 个首次修复候选均通过 Dafny 和最终落盘文件重验。存在 1 次控制器转交提示时的遗漏，该次保留结果但排除出策略比较。因此有 7 次符合已知输入条件的运行、1 个完整的四组题目块，不能写成“完整有效的 2 题 × 4 组对照”。目前只证明了失败代码到合格工件的修复流程可运行，未证明义务调度提高通过率。

## 设计和实际执行

- 协议：`common_failure_codex_repair_v1`，与上一轮从零生成协议分开。
- 两个已有开发题：整数平方根、二分下界查找；每题一个人工编写的失败起点，四组各一次。
- A：当前代码与完整公开诊断；B：A 加证据状态；C：B 加确定性选择的目标；D：每次独立修复原始失败代码，不获得后续候选反馈。
- 四组使用相同的通用修复指令。公开契约固定，允许整体替换实现；没有强制只能修改指定位置。
- 调度种子 20261007，题目内随机化组顺序。每次运行最多 3 次模型请求、4 次题内全文件验证；最终重验计入预算。每次验证 15 秒、队列响应 300 秒、任务 1200 秒。
- 每个模型请求使用新的 `fork_turns=none` 子代理；会话日志记录模型 `gpt-6-astra`、推理强度 `high`，8 个会话均未观察到工具调用。父控制器没有修改模型候选。
- 参考实现和失败起点先经过真实 Dafny 4.11.0 检查；同题四组回放完全相同的初始验证证据。该初始失败不计作模型生成失败。

冻结配置、任务/源码/工具链哈希、执行顺序和计划提示见 [batch.json](../logs/common-failure-repair-20261006/batch.json)、[jobs.json](../logs/common-failure-repair-20261006/jobs.json)、[initial_messages.json](../logs/common-failure-repair-20261006/initial_messages.json)。

### 实际修复内容

平方根四组都保留逐次递增的循环：将初值从 `r := 1` 改为 `r := 0`，循环条件改为 `(r + 1) * (r + 1) <= n`，终止度量改为 `n - r * r`。A/B/D 最终文件相同；C 额外加入平方展开的断言。初值和循环条件分别涉及零输入与越过下取整结果的问题；终止度量是观察到的修改，不能仅凭修改就断言原度量自身错误。

二分下界四个输出均保留 `lo/hi/mid` 二分结构，将 `s[mid] <= key` 改为 `s[mid] < key`，加入左右已排除区间的量化循环不变量及证明断言。D 额外包了一层语句块，仍通过合法性检查。没有输出替换成线性扫描。此分类来自最终源码检查；本轮没有执行复杂度验证，也没有记录模型内部修复步骤，不能把完整方法体输出解释为经过验证的局部修复规划。

## 协议偏差及审计

第 7 次请求 `006_binary_lower_bound_state/001` 在父控制器手工转交时，漏掉了 `task.methods[0].header` 中的 R3 后置条件：

```dafny
ensures forall i :: 0 <= i < p ==> s[i] < key
```

这条要求仍在该请求的失败源码、自然语言需求和证据状态中，最终可信验证文件也完整保留了它。因此验证通过是真实的，但模型实际输入与计划提示不一致，不符合控制变量要求。保留原始结果、公开偏差并排除比较；没有替换样本或隐蔽补跑。见 [偏差记录](../logs/common-failure-repair-20261006/protocol_deviations.json)。

[工件审计](../logs/common-failure-repair-20261006/audit.json) 核对了完整运行清单、冻结源码/任务/工具链、初始失败证据、计划提示、队列请求与响应、原始候选、最终验证和状态身份。8 个原始响应与子代理最终输出逐字相符。各组计划公共字段一致，B/C 的计划状态一致，只有 C 带目标。

[会话审计](../logs/common-failure-repair-20261006/session_audit.json) 核对了新建上下文、模型、推理强度、零工具调用及用量。平台把父调用和子会话中的任务文本加密保存，无法从这些日志独立重建实际明文提示；不能把计划提示哈希当成实际转交一致性的证明。已知偏差来自控制器主动发现并记录，其余转交一致性仍依赖控制器记录。扩大实验前必须消除手工转抄，并验证实际发送文本的哈希。

原始 `summary.json` 是执行器产出的验证结果汇总，未识别外部手工转交偏差；它的 8/8 仅描述工件验证。[comparison.json](../logs/common-failure-repair-20261006/comparison.json) 按偏差记录明确排除该行，标记 `complete_comparison_matrix=false` 并保存各组有效分母；不得单独引用原始汇总宣称有效对照。
