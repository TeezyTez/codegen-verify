# 多轮代码开发中的需求保持与约束遵循

整理日期：2026-10-14。

本专题研究多轮代码开发中，用户提出的需求和约束如何持续生效，以及它们为何会被遗漏、误解或违反。核心区分是：约束没有进入当前上下文，与约束已经进入上下文但没有被正确执行，是不同的问题，需要不同的诊断和工程措施。

## 研究问题

1. 在多轮对话中提出一条约束后，编码代理通过什么机制持续获得并遵守它？哪些环节可能失效？
2. 当前编码代理及相关工程框架如何处理需求忽视、遗忘和过早宣布完成的问题？各类方案能够保证什么？

## 当前结论

需求持续生效需要经过“保存与传递、正确理解、执行、验证”多个环节。外部规则文件、结构化任务状态和上下文恢复提高约束的可获得性；自动检查与需求验收用于发现或阻止执行偏差。关键约束应尽量同时具有明确文本和可核对的验收证据。

这里的“现有方案”依据所列产品文档与工程案例归纳，不代表行业采用率调查或受控效果比较。后续研究问题仍是候选问题，本专题不新增实验结果，也不将现有项目的 Dafny 实验解释为多轮需求保持的实验证据。
