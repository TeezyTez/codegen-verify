# 大规模实验方案：规约证据是否改善代码生成决策

日期：2026-10-09。状态：本文件保留初始计划及执行前修订；实际运行数量以冻结队列和结果报告为准。本方案不是对现有八题运行器的“扩大题数”配置。正式运行前必须冻结任务、控制器实现、模型身份与完整提示词的哈希。

## 研究问题与可证伪结论

所有组都拿到相同的完整规约、初始骨架、Dafny 反馈、工具及生成预算。从零生成实现和所需证明。研究问题是：**把验证证据维护成有版本、有依赖的状态，并据此选择下一步生成目标，能否提高有限资源内的最终正确率？**

主要比较 D−C，检验“根据证据改变目标”是否优于有相同状态的结构顺序调度；关键实用比较 D−A，检验外部控制是否优于强模型自主组织。B−A、C−B 用于分离状态整理与固定目标组织的贡献。修复成功、诊断减少、某个方法通过，都不能替代最终完整程序通过。

结果解释提前固定：D 仅胜 A、不胜 C，支持结构化流程但不支持自适应调度；D 胜 C 却不胜 A，说明控制器有内部改进但未超越自主 agent；仅在多依赖层任务胜出，贡献应限定为复杂依赖下的生成控制；差异接近零且区间仍宽，结论是证据不足，不能称等效。区间足够排除预设的实用增益，才可否定该版本的实用收益。

数据准入必须在看到被测各组结果前完成，逐题保存证据与排除原因：

1. 固定原始自然语言、所有外部契约和共享定义；只开放实现及指定的新证明/辅助声明区域。参考解答不进入模型沙箱；预置的可执行助手检查是否泄漏核心算法。
2. 对参考与原任务做 AST 级契约/共享定义一致性比较；参考验证成功不等于解的是同一份题。去掉占位 `assume {:axiom} false` 必须是受控的骨架转换，并记录原始→骨架差异，绝不能把它保留为候选的一部分。
3. 在固定工具链重新验证参考，拒绝 assume/axiom/验证关闭/缺证明体/终止豁免等信任绕过；记录每个目标及新增辅助声明的验证覆盖。词法筛查仅提供警告，不能代替 AST/解析后的验收。
4. 检查非空输入见证；用常量、空输出、边界错一、跳过循环等适用突变寻找可利用的弱契约；保存见证和杀死/存活结果。杀死有限突变只增加信心，不证明契约完备。
5. 独立审阅自然语言与形式契约是否一致、辅助函数是否已包含答案。所有候选由两个隔离审阅流程检查，分歧在冻结前裁决；模型审阅只是筛查证据，不能包装为形式证明。若需修正规约，发布修订版和 diff、单独报告。
6. 保留 source/source-id、原文件、已知 near-duplicate-group、规范化契约/AST、语义重复审阅结果；合并成根题族。跨来源同题、同 NumPy 运算变体、同文件多个方法不得跨开发/测试边界。
7. 无发布参考的 467 个非 DD tasks 不应因未知可满足性直接计失败，也不能悄悄删除：独立于 A–D 补参考/见证，完成相同审计后准入；未解决者形成明确的挑战池。报告主集合中“上游已有参考/独立补参考”分层，承认可解性筛选偏差。

本轮已观察到 DafnyBench 的弱契约：BinarySearch 返回 −2 可绕过原后置条件；因此“验证通过”单独并不足以准入。BAF 参考词法初筛有 74 份带至少一种风险标记；可能含误报，需解析复核，不能直接判定 74 份都有漏洞。

## 四组：只改变控制策略

| 组 | 自动提供的结构 | 谁选择下一步目标 |
|---|---|---|
| A 自主 agent | 完整规约、当前源码、原始完整工具结果、同容量历史 | 模型自主规划，可自己建立状态和使用所有工具 |
| B 状态辅助 | A + 结构化证据账本 | 模型自主选择 |
| C 结构顺序调度 | B + 当前目标 | 根据当前候选依赖图计算稳定顺序，按固定轮转规则选择 |
| D 证据调度 | 与 C 相同的账本、目标字段和动作空间 | 使用当前结果、依赖和历史进展的调度器 |

A 必须是认真实现的强自主循环，允许改实现、写不变量/引理、拆辅助函数、重新生成和自主选择检查；不能拿一次生成或无历史修复当主要对照。四组均能访问同样的基础解析结果，B 的优势只是账本自动维护。所有组都按相同规则自动验证候选，禁止给 D 额外隐藏检查。

控制器 v1 的实现定义（代码位于 generation/public_benchmark；正式主矩阵前冻结）：

- 每条状态绑定规格、候选、工具链和声明身份。区分 `unobserved / failed / locally_passed / closed / stale / unknown`。局部通过但调用者依赖未闭合时保留条件性；编辑后按解析出的依赖重新检查，无法确定影响范围则保守失效。解析调用图不冒充 SMT 的精确 VC 依赖图。
- 语法/类型阻塞是 C、D 共同的第一优先级。C 随后按当前候选的依赖 SCC 拓扑序、声明 AST 序号巡回（允许新助手改变结构顺序；不根据失败与进展优先级改序）；跳过当前 closed 项，每目标最多连续两次，继而轮转。C 不利用失败类别、回退或进展历史改变该顺序。
- D 的候选目标集合与 C 相同。先处理依赖未闭合却被上层使用的目标，再处理先前 closed 而当前明确 failed 的回退目标，再处理当前可定位失败，最后处理 unknown/unobserved。组内按未闭合依赖的下游受影响声明数、等待轮数、稳定 AST ID 排序。一个目标连续两次未取得经新验证确认的进展，冷却到其它可选目标各获得一次机会；若无其它目标则保持该目标，允许模型改变解法。
- “进展”仅指新增完整声明通过且其依赖闭合，或目标文件从解析失败变为可验证；不以报错数量减少定义进展，不把诊断消失视为义务已证明。终态只由全程序验证与固定准入检查决定。
- C、D 都让模型选择实现修复/证明修复/重生成的具体动作；主试验仅强制研究的目标选择。记录是否遵循目标及实际改动范围；不因模型未遵循 D 而删样本，主分析按分组意向处理。
- 同一任务的初次目标只依赖冻结规约，两者使用同样初始规则；其后差异才来自历史证据。目标之外的代码允许编辑，避免误把“禁止全局修复”当算法。

现有 `generation/obligations/state.py` 只是状态优先级加诊断/hash 排序，`policy.py` 只是目标提示。它不具备上述依赖闭合调度。必须保留旧版本哈希，把新实现独立标为 v1，不能将旧实验算成 v1 数据。若采用不同调度规则，须在正式测试前更新本协议并冻结，不能见结果后再解释规则。

## 规模与资源：增加独立题，保留完整预算曲线

先按根题族划分 64 个开发族，其余全部合格原生族进入测试。目标规模约 1,000 个独立测试族，但**不为凑数降低准入标准，也不把这个数当作已取得的样本**。若合格数较少，报告真实 N 和统计分辨率；需要补充时，在查看组间结果前按已冻结生成规则增加独立根族。

主矩阵：`N 个测试族 × 4 组 × 3 次独立重复 × 2 个固定模型 = 24N 个会话`。N=1,000 时 24,000，会话 N=800 时 19,200。每族若含多个不可合并的合法任务，全部保留但族内等权，不能重复增加主分析权重。

每会话最多 12 次模型行动、最多 12 次候选完整验证；同一候选缓存结果但显式记录请求。每次模型行动同一输出与推理配置、最多 16,384 输出 token（含推理计费口径按接口锁定）、240,000 会话总 token 上限；支持不一致时使用两模型共同可用的上限并在运行前固定。验证单核、每次 120 秒墙钟上限；运行器模型单请求超时 900 秒、会话上限 3 小时。达到任一上限即停止，不能专给某组加轮次。首次合法全程序通过即成功停止。

报告第 1/2/4/8/12 次行动的累计成功率、固定 token 上限下的成功率、实际延迟/验证消耗。这些资源上限用于定义同等条件的研究问题，不是为了节省费用。没有完整 usage 时不得声称算力严格等价；行动数公平和 token 公平分别报告。模型重试只限明确定义的传输错误，限两次、保留请求日志；模型输出不佳和验证失败不能当传输错误免费重抽。

模型1沿用用户指定的当前 Codex 生成通道；模型2是独立模型复验角色。**具体可复现模型身份、后端、采样参数、隔离运行方式尚待接口能力确定；这里不虚构一个可调用的“当前模型 API”，也不悄悄替换为 DeepSeek。** 先完成模型1的全量设计与运行能力；在同一规约和策略冻结后做模型2外部复验，分别报告，不平均掩盖差异。若只能运行一个模型，规模为 12N，结论也限定该模型。

开发试运行为 16 开发族 × 4 组 × 1 重复 × 模型1 = 64 会话；只检查加载、合法性、隔离、全程日志、目标选择能实际分叉及终态验收。没有正向效应不阻止主实验；控制器根本没有参与、串组或加载错误才阻止。正式分组按任务×模型×重复组成区组并随机交错派发，固定随机种子，禁止同一模型上下文看到其它组答案。

## 机制与外推：不只比较一个通过率

1. **自然共同失败状态。** 在事先抽定最多 100 个测试根族上，使用独立中性生成器的首个失败状态，向 C、D、D去依赖、D去版本失效四种策略提供完全相同代码和真实历史；每个状态 3 重复。每族最多一个状态，生成器一次通过者记为未进入此条件，不改抽“D容易赢”的题。其结果是条件修复效应，不能替代从零生成的主效应。
2. **受控生成集。** 50 个独立根程序，每根 3 种依赖深度 × 2 种证明耦合 × 2 种修改传播范围 = 600 变体。编写可构造的规约、参考、输入见证及已知错误突变，再独立验证；不是让被测模型同时自由写题、写答案和自评分。开发/测试按根族切分，构造规则冻结后留出测试种子；分别检验耦合强时调度收益是否增加、状态失效是否减少重复错误。
3. **AlgoVeri 外部集。** 开发结束前冻结审计规则，避免失败后调参又称外部测试。所有准入算法运行同一四组；报告功能正确率，算法身份/复杂度只在有额外独立验收时另报。没有参考而可满足性未确认的题单列开放挑战，不混入主分母。

机制指标：每 100 个行动获得的新 closed 声明数、真实回退率、重复候选/重复失败链、选择目标改变率、依赖深度分层效果。局部指标可能下降而最终通过率上升；不能按“错误更少”自行给 D 加分。所有复杂度分层基于冻结任务/参考的结构或独立开发模型，不能用被测 D 的成败定义“困难题”。

## 统计分析与结论门槛

主指标是 12 行动内合法、无绕过、全目标及辅助证明均验证通过的会话比例。自然语言一致性/可运行性用冻结的独立检查作附加严格成功指标，并与形式通过率并排报告；不把验证器能证明的范围扩大为完整软件正确性。

先在每个根题族内对重复与变体平均，再计算各组的等族权重成功率及配对差。按根题族 cluster bootstrap（10,000 次）计算置信区间；同模型内 D−C 与 D−A 为两个预先指定的关键比较，使用同时区间/预先选定的多重检验校正。模型1为主要验证、模型2独立复验；B−A、C−B、分层和机制指标明确为次要分析并报告多重比较范围。

实用效应阈值定为 +5 个百分点。主结论同时看效果量、区间、资源曲线及机制触发；不得把 p<0.05 的微小差异写成重大改进。N=1,000 不是功效保证：配对二元差在不一致概率 q=0.2/0.3/0.5 时，单一比较、近似 80% power 检测 5pp 分别需要约 620/934/1,561 独立题；多重比较及聚类会改变需求。正式实施前在开发集估计不一致与组内相关，冻结功效模拟和最终样本数，不能查看测试 p 值后继续加题直到显著。所有任务一次通过时应报告天花板效应，而不是设计新坏种子回填同一主测试。

依赖超时、工具错误、协议拒绝、模型中止都保存。已开始会话按意向处理报告失败原因及操作成功率；明确基础设施失败另做敏感性分析，禁止静默移除某组失败。首次 30 秒参考预检超时不等于不可解，正式准入按统一 120 秒标准再验。

## 最快推进顺序与当前状态

已完成：三套公开资产固定版本、逐文件哈希校验；BAF 3,029 行机器清单及 1,754 个参考任务清单；DafnyBench 782 次真实参考验证。BAF 全量参考验证已发起，结果写入 `data/large-scale-20261009/baf_preflight/`。这些均为数据/工具预检，模型调用数为零。

DafnyBench 当前结果：504 全部观测批次通过、236 tool_error、24 verification_failed、12 timeout、4 unknown、2 parse_error。426 份通过且没有本轮词法警告，但其中仍包括已发现的弱契约题，所以 426 也不是正式准入数。逐条检查原始输出发现 236 个 tool_error 均含“警告被视为失败”的信息；既包括旧语法，也包括信任绕过等警告。这是当前命令的严格警告策略，不能解释为 236 个实现均错误，也不能无条件忽略警告并算成功。原始结果不变，附加解释保存于 `reference_census/tool-error-annotations.json`。

BAF 原生 tasks 的 1,891 行按已知原题 ID、上游重复组和完全相同的冻结字段初步合并为 1,773 组。它们仍需跨来源语义去重和契约审计，所以本轮正式准入数仍为 0；计划文件明确 `run_enabled=false`，没有用虚构的 1,000 个已准入任务生成可执行矩阵。

接下来三项是主实验的必需工程，按依赖顺序推进：

1. **数据与完整 Dafny 适配器。** 支持公开题共享定义、引理和标记生成区；做 AST 级冻结契约/声明覆盖审计。不能继续沿用只容许窄子集语法的八题 profile，也不通过删题目定义迁就它。
2. **统一 agent 循环与控制器。** 在相同循环中实现 A/B/C/D，冻结状态失效、依赖闭合和目标选择；用独立开发族检查。当前 `file_campaign.py` 硬编码八题且依赖人工交接，不能承载宣称的 24N 批量实验，需要通用队列及隔离生成 worker。
3. **盲化冻结并派发主矩阵。** 写入逐题准入清单、根族和 split、提示词/策略/工具链哈希、实际模型身份；才生成真实 job roster。吞吐由独立队列、候选缓存、CPU 验证池、模型后端背压控制；不能用重放缓存答案或复用上组上下文制造“高速模型实验”。

结论：现在已有足够大的可获取候选池，没必要首先自产数千个相似题。应先把公开原生题变成可信评测，再直接检验“外部规约控制是否比自主 agent 更有效”。正式成功率、最终准入 N 和创新成立与否，本轮均尚无答案。


## 2026-10-09 执行前补充裁决

首个开发链路队列为 3 道题 × 4 组，共 12 次真实生成，全部首次通过。它只用于检查传输与验收，不纳入正式主测试。独立代码审阅发现并修复：C 的连续服务次数曾被证明进展重置；无效中间候选曾清除历史已证状态；同目标 C/D 提示包含不同 reason 文本；统计完成状态只核对总数。修复不根据测试效果调参。

C 采用当前候选结构的固定轮转规则，D 增加证据优先级和无进展冷却；初始相同目标产生相同提示。保留目标原因于审计日志。每轮额外离线计算同一账本上的 C/D 目标及可编辑未闭合声明数，不反馈给模型；由此统计实际存在选择分歧的机会。

模型通道固定为 Codex CLI 请求 gpt-6-astra/high，现有登录，fresh ephemeral 无工具会话。CLI 输出不确认响应端模型版本，故仅能报告请求身份。无外层免费重试；传输故障保留为失败。单次输出上限由事后拒绝执行，不能称后端硬限制；完整实际 usage 另存。当前只运行模型1，任何后续模型复验单独冻结及报告。

恒定族差值时，经验 bootstrap 的零宽区间无辨识力；改报差值范围 [-1,1] 的 Hoeffding 保守区间，并说明小样本无法判等效。普通非退化样本保留预定配对族 bootstrap。

原方案的大规模目标并非已完成数，正式实际 N 由冻结前准入、语义去重和开发切分决定。最早参考兼容性和语义审查均不算被测代码生成试验。


### 主矩阵冻结前的效率与统计裁决（本节覆盖上文冲突条款）

1. 主矩阵按最终语义根族取一个代表任务，避免将同一运算的多个包装重复运行而增加不了独立样本。代表选择完全不读取任何 A–D 结果：按发布参考中新增辅助声明数最多者优先，其次参考声明总 token 数，最后按任务 ID 排序。选择刻意偏向有较丰富证明结构的版本，因此估计对象是这些预选代表任务，不能称 BAF 原始行的无偏平均。每代表依旧四组、三次重复；固定单一模型。
2. 开发划分保留原计划的 64 个根族：已执行的 16 个开发种子及全部同族必定开发，其余开发族按固定哈希种子补足 64；若最终不足 128 族，则额外开发预留不挤占一半以上题族。此划分在正式生成前完成，开发结果不参与代表选择。
3. 开发 66 个行动中，可编辑未闭合声明不少于两个的机会为 0，C/D 同状态选择分歧为 0。这说明自然开发样本未激活目标选择机制。工程夹具已验证调度器可分叉；主矩阵仍用于测量公开任务上自然发生的选择机会和总体效用，不能单凭此矩阵的零差异判定依赖调度机制无效。依赖丰富程度按私有发布参考预先分层，主矩阵之后不得因结果不显著追加新题改变同一主分母。
4. 当每个独立题族的配对净差均为零，用精确单侧二项上界 q=1-alpha^(1/N) 给出 [-q,q]，因为 |E(delta)|<=P(delta!=0)。这是对零非零族观察的保守界；其他常数非零差值保留 Hoeffding 边界，非退化样本采用预定 bootstrap。两个关键对比每个 alpha=0.025。小样本开发比较仅为描述性。
5. 发现并修复 Unicode/换行导致的 AST 源位置偏移后，主矩阵使用新版本编译器桥，重新保存最终准入 AST。旧开发结果、失败、源码快照和旧规约审阅全部保留。只复用经相同 public 输入哈希关联的语义审阅，不复用旧候选结果作为新模型实验。
6. 最终执行前代码复核发现上文“解析失败变为可验证也计进展”的文字与实现不一致。本次固定采用实现已有的更窄定义：仅新增 closed 声明重置 D 的无进展计数；仅消除语法错误不重置。解析/类型阻塞仍是 C、D 共同的优先目标。此裁决在正式主队列生成任何结果前作出，没有修改或观察主队列效果。
7. 突变审计用于寻找可被接受的错误实现。超时只记未解决，不记 killed、也不单凭超时排除已经通过双语义审阅、真实参考和可达见证的题；存活者必须逐条裁决。正式报告公开未解决突变及清理诊断，因此不宣称所有错误实现已被排除。补充编译指标只做 Python 翻译和语法编译，不执行程序，不改变形式验证主终态。
