# 文件交接开发实验：执行前冻结方案

用户在公共失败修复实验后要求继续。目标是消除手工提示/答案转抄，扩大开发题覆盖，检验固定规约义务与证据状态对修复的作用。此方案在新题模型采样前保存；不是确认性实验。

## 固定设计

协议 `verified_file_repair_exploratory_v1`。8 项开发任务 × 4 条件 × 3 重复，共 96 次运行。题目为 cube_root、division_pair、first_argmax、merge_sorted、prefix_maxima、reverse_copy、search_pipeline、triangular_sum。任务与重复构成 block，block 顺序和组内顺序用种子 20261008 冻结。预定任务缺失、参考验证失败或起点未失败都拒绝启动，不静默缩小矩阵。

每题共享同一个人工失败起点和同一份真实初始诊断。A 普通完整反馈；B 另加状态；C 另加目标；D 每次独立修复原始起点。公开契约和通用修复指令相同。允许完整替换方法体；不要求保持参考算法、局部编辑或指定调用路线。原始失败不计为模型生成失败。自然生成实验与这个条件修复实验分开。

每运行最多 3 个 solver 请求、4 次全文件验证（包含最终重验）；验证 15 秒/次，模型会话等待 600 秒/请求，总运行 2400 秒。最大 288 个 solver 请求、384 次题内验证；8 次参考及 8 次共享起点验证独立记数。作者阶段的所有准入尝试、有限 witness 检查和入口探针另计，不进入模型分母。无强制 token/美元上限，不能与严格 API 预算实验合并。

## 输入和响应交接

每个请求使用一个新建、无父会话历史的子代理。仅授权一次固定 `functions.exec` 调用：用可信加载器读取本请求，检查 request ID、消息哈希、完整 dispatch 哈希和重建结果，输出 receipt 与全部 SYSTEM/USER 文本。拒绝修改、重复加载、过期或过大输入。此后不得调用工具、读仓库或验证候选。

加载器不是 OS 沙箱；不能声称模型无法读取其他文件。控制器在接受答案前，检查会话中实际的工具命令完全匹配、stdout 与完整冻结提示一致（仅规范化 Windows CRLF）、没有额外工具、只有一个入站任务、原始最终答案唯一。任务 bootstrap 在平台日志中可能加密，但实际加载命令及工具输出可核验。任务参考、作者证据和其他组结果不进入加载输出。

答案从选定子代理会话直接写入队列，不由父控制器重新打字。记录原始回答、会话哈希、实际模型/推理强度、累计 token 和加载凭据。一次 solver 请求通常包含选择加载工具和工具返回后的回答两个模型阶段，不能称为一次底层推理调用；所有阶段用量合计。平台系统上下文存在，各组都承担同一加载过程。

CLI 的两次本轮探针分别遇到沙箱初始化拒绝和请求超时，未成为实验样本。按官方 [非交互入口说明](https://developers.openai.com/codex/noninteractive/) 测试的 stdin 方案暂不可用。文件加载 canary 已返回完整标记；实际命令与输出审计通过，单独保留在 `logs/file-handoff-canary-20261006`。

## 题集与解释边界

8 项均为开发资产，契约语义的独立人工审计仍 pending。reverse_copy 继承已有 sequence_reverse 算法，cube_root 与先前平方根题相关，search_pipeline 含已有下界查找子问题；不将跨批次复用当新增独立题。triangular_sum 和 division_pair 有闭式/内建运算捷径；没有因其容易而事后删除。合并、前缀最大值和索引题加入多重量化/集合性质，但难度还需实测。

报告完整任务级及重复级结果、首次修复通过、预算内通过、模型候选失败后的恢复、验证调用、token、时间和源码修复类型。重复不等于独立题。成本未知就留空，不用模型输出自报用量。样本少且均来自开发设计，不作确认性显著性或等效结论；没有随机目标消融，不推断选择器最优。

## 数据质量停止规则

源码、工具链、任务、模型身份或输入交接不匹配时立即停止派发新请求，保留已花用量和所有工件，修复后新开批次。基础设施错误连续 3 次停止批次诊断。协议偏差不得自动重试成干净样本。算法候选失败按预算继续，不能因为结果不理想删题、增加重复或提前结束。预定 96 次只有全部完成且审计通过，才报告完整矩阵；中断时明确列出已完成、失败和未运行。
