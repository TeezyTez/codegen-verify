# 新主线：固定可信规约下的代码生成

设计日期：2026-09-13。状态：研究方向与实验设计，**尚未实现新生成协议或执行生成效果实验**。
更新：2026-09-14已实现受限Dafny生成协议、12项人工诊断任务、四条件、模板基线和真实本地验收。
这里保留原设计以供比较；具体实施偏差和结果见 [生成执行报告](GENERATION_PILOT_REPORT.md)。
模型效果实验、独立外部数据和实际PSM转换仍未完成。
取代“依赖引导修复调度”作为下一阶段研究主线；旧代码和原始运行不变。
本次未取得用户的真实 PSM 样例，默认按“结构化平台模型＋明确行为约束”设计，不能称为已适配某个工业 MDA 工具。

## 1. 研究对象与核心问题

长期：让可信设计条件约束代码生成，并为最终交付物提供可追溯的符合性证据。
第一阶段不生成/修改目标规约，不优化证明修复顺序，不同时研究需求理解。

候选研究问题：

> 在输入规约、平台约束和资源预算固定时，将其中可执行的约束变成框架控制的生成边界与验收义务，
> 能否比仅提示规约或通用验证反馈 Agent 更可靠地生成满足全部已声明条件的代码？

这不是已证实的新方法。先做失败现象与工具覆盖率研究，再判断“边界与验收义务”是否值得成为方法贡献。
“给定规约生成代码”本身已经是既有任务；仅获得更高 Dafny 通过率不足以论证独创性。

## 2. 三类输入不能混为一谈

| 输入 | 已确定的东西 | 仍未确定的东西 | 允许的结论 |
|---|---|---|---|
| 形式行为规约 | 前/后置条件、状态不变量、允许副作用等 | 满足条件的实现、证明辅助内容 | 相对于规约和可信工具的正确性 |
| 结构型 PSM/配置 | 接口、类型、字段、映射、平台约束 | 若未声明，业务行为仍未知 | 结构/配置符合性，不能自动声称功能正确 |
| PSM＋行为约束 | 结构、平台、行为要求 | 实现策略、可证性、性能等未固定选择 | 各类义务分别检验后的符合性 |

PSM 是平台特定模型，不是任意 JSON 的别名，也不天然是完备形式规约。
OMG 对 MDA 的说明包含 PIM→PSM→实现的变换链；因此模型到代码的确定性变换是必要比较对象。
本地 JSON 若仅用于序列化，应称为“PSM 投影/实验配置”，并给出到原模型元素的对应，不能自称完整 MDA 实现。
[OMG MDA 说明](https://www.omg.org/mda/specs.htm)；[MOF Model to Text 标准入口](https://www.omg.org/spec/MOFM2T/1.0/About-MOFM2T)。

“金标准”是有来源的实验信任假设，不是自然成立的事实。每条约束需要记录：
来源元素、确切语义、来源版本、审查状态、如何检查、适用范围、工具状态。
未知规则不得由 Agent 自行补成隐藏验收要求；缺失/冲突/不支持要显式报告。
参考代码是一个满足者，不是唯一正确实现；不能用文本相似度作主指标。

## 3. 推荐先做的场景与明确不做的事

先做**配置化业务模块的核心逻辑生成**：用函数式状态转移表示配额分配、审批守卫或规则决策。
只选择一个场景族开跑，默认“资源配额/批量分配”，便于构造共享状态约束、循环、边界与组合关系。
这只是可操作起点；若真实 PSM 主要描述其它对象，应按它的明确语义调整，不强行套配额故事。

最小例子：输入规定容量 cap、已有分配 used、请求序列 requests、固定接口；
要求请求非负、接受集合的总量不超过剩余额度、拒绝项不改变状态、分配规则确定、其它租户不受影响。
行为规约描述允许的结果关系；算法实现和循环不变量由模型产生。
如要求“最大化利用率”，须定义最优性和并列规则，不能在实验时偷偷添加；v0 不默认承担优化问题。

结构映射若可直接模板生成，不交给 LLM 冒险重写。剩余业务实现交给 LLM 的理由必须有证据：
例如当前模板未覆盖的控制流/跨操作约束，而不是故意从基线中删掉已有生成规则。
若输入提供了完整可执行转换表，传统解释器/编译器可能已经足够；这应成为可接受的结论。

v0：一个验证后端，一个明确的整数/序列/状态元组子集，无数据库、网络、并发、分布式事务。
金额/配额采用明确定义的整数单位；不把数学整数证明自动解释为 Java int 不溢出。
不做完整企业应用、全量 UML/OCL、PIM→PSM 推导、多语言转换或安全认证。

## 4. Dafny 的角色及两条证据边界

**先跑形式规约给定的生成核**：Dafny 是目标语言和验证器，最大化复用现有环境。
输入为人工审计的契约、接口、公开说明与约束清单，输出为实现和必要证明注释。
这一步测“固定条件下生成”的决策质量，不声称已完成 PSM→工业代码。

**随后才接 PSM 投影**：对一个受限 profile，把 PSM 的显式字段映射成接口/常量/契约或静态检查。
转换器在实验前由策划者建立并冻结，不由被评测模型临时翻译自己的验收标准。
必须先审计转换是否遗漏语义，独立测试前后含义；遇到不支持的配置拒绝而不静默丢弃。
不要直接把旧 SpecIR 的 result_expression 当成目标：它可能已经编码完整算法，导致生成任务退化为抄写。

如果未来输出 Java/TypeScript 等工业代码：

- 可优先复用该语言现成验证/静态检查/模型测试工具，不强制经过 Dafny；
- 若验证的是 Dafny 投影，必须另外证明/检验投影与最终代码的对应；
- 核心函数已证明、胶水代码只有测试、框架只检查结构时，分开报告，不能称整个应用已形式验证。

## 5. 只保留一个候选方法主题

主题为“**固定约束的可执行落实**”，不是再加一套规划/图/RL系统。
最小流程：读取可信输入 → 确定性生成已确定的骨架和外置验收义务 → LLM生成剩余实现 →
检查与必要修正 → 从干净环境检验最终实际工件。

两个落实位置须通过消融分清，而不是混称一个黑盒优势：

1. 生成前：哪些内容已经由输入唯一确定，是否由固定骨架保留？
2. 生成后：是否让模型使用完整的可执行验收反馈？

独立 oracle 对所有条件始终相同、始终不可编辑。去掉骨架或反馈也不能允许改弱规约过关。
骨架只包含输入可确定内容，不得注入参考算法、隐藏测试或手写关键修复。
约束 ID→验收项只是可追溯工程设施，不单独包装成论文算法。

## 6. 实验设计

### 6.1 阶段 E0：确认“是否需要 LLM”及评测是否可靠

先策划12个开发任务，至少3个独立来源/设计家族；来源不足时不伪称已经满足。
覆盖三层：纯结构/完全可生成、单操作行为、跨操作/约束交互。
每任务都有原始条件、语义说明、正确参考、接口与验收；从签名/空实现开始，**不给错误算法作为起点**。
空实现可能编译错误，不要求“初始必须verification_failed”，以免把生成任务错误地过滤掉。

冻结传统模板/规则生成器，测支持覆盖率与已支持任务的正确性，人工维护时间单列。
完整可解释的模型还应比较直接解释执行；不得只用一个明显不完整的模板基线证明LLM优越。
它们不支持的任务仍在整体分母中，但同时报告“unsupported”和覆盖率，不把它等同逻辑错误。

独立构造已知错误实现检验 oracle：漏守卫、边界偏差、错误字段映射、跨操作状态破坏、非法配置等。
每个反例应有人审计“确实违反给定规则”；关键故障类别若检不出，先修评测而不是上线模型实验。
oracle与生成骨架不能仅依赖同一错误转换器而互相印证；需要独立样例/参考解释和转换测试。

### 6.2 阶段 E1：受控主比较与2×2消融

所有模型组接收语义相同的可信输入；无骨架组也有等价接口/平台说明。统一候选输出语法限制、安全沙箱、模型、温度及资源上限。
“无反馈”指在线不返回语义检查结果，最终仍接受全部外部验收；两组可使用相同编译反馈。

| 条件 | 固定生成骨架 | 在线语义反馈 | 意义 |
|---|---|---|---|
| G00 多次生成 | 无 | 无 | 同预算独立候选，不用旧失败信息 |
| G01 通用验证Agent | 无 | 有 | 强基线：完整规约、错误、同类工具权限，自主生成修正 |
| G10 骨架内生成 | 有 | 无 | 单独测减少生成自由度的效果 |
| G11 骨架内验证生成 | 有 | 有 | 候选主方案 |
| T 模板/规则/解释器 | 由传统工具决定 | 不调用模型 | 测传统方法的覆盖率与成本 |

G11 vs G01 检验骨架增益；G11 vs G10 检验反馈增益；完整四格检验二者交互。
这不是证明“规约有用”的信息不对称实验。若额外比较自然语言输入，必须作为另一项输入研究，控制语义等价，不能混入主因果结论。
单次生成成绩可读取 G00 的第一个候选，单独命名；不能与多轮Agent结果混叫pass@1。
G00/G10 按预先固定顺序在线验收，第一个通过者可停止；若失败不把结果用于后续候选生成。
所有检查/最终重验成本均计入对应运行，不允许无反馈组免费产生更多候选。

资源起点：每run最多6模型调用、10次完整验收（最后1次预留）、48k token、输出上限2048、180秒。
这只是继承旧框架的dev初值；若空实现生成普遍截断，在dev上统一调预算后冻结，不能为方法组加预算。
各工具子检查次数与时间单独记录，避免把昂贵多工具检查包成“1次”造成虚假公平。

12开发任务 × 4模型条件 × 3重复 = 144模型run；模板12任务不需要随机重复。
上限864模型调用、1440完整验收、6,912,000 token（尚未授权执行）。真实模型价格未知不填美元数字。
先做少量模型连通性与格式测试，独立标记为smoke不并入预注册统计；正式E1前同一任务清单/配置/生成器版本全部冻结。

### 6.3 阶段 E2：独立泛化，不是继续改dev分数

E1明确痛点与机制后，再策划新的来源项目/设计家族测试集，样本量按dev方差和成本决定。
同一PSM的字段重命名、阈值变体、组合派生必须同组，不随机拆到训练/开发/测试。
纯形式规约任务和PSM派生任务分别报告，不用前者高分代替PSM转换有效性。
优先真实公开模型来源；人工构造记录来源、规则和偏差，不能称为工业案例。

另设非主指标的输入诊断集：缺规则/冲突/不支持PSM，应明确拒绝或标记缺信息。
不要把无解任务当正常生成失败，也不要将其用于训练主方案后混入测试。

## 7. 指标与可支持的结论

主指标：合法工件在预算内，通过该任务预先声明的所有适用验收义务的比例。
形式验证任务要求全部目标义务已证明；仅测试任务称为“通过符合性检查”，不称“形式正确”。
支持范围外/超时/未知/编译错误/预算耗尽/工具错误分列，主分母不得只保留可验证的成功子集。

必须拆开报告：结构符合率、行为测试通过率、形式证明通过率、任务级联合成功率、
token/费用/全耗时/各工具调用、修改规模、人工准备成本和转换器维护工作。
条款平均通过率不能代替“所有条款同时满足”；表面需求ID覆盖不能代替语义检验覆盖。
失败分类：未遵循接口、漏约束、约束组合出错、证明不足、环境/转换器问题。
先人工审计代表性失败，不能把verifier失败自动归为代码bug。

按任务/重复配对，来源组聚类估计区间；3个来源dev的区间只作探索，不声称足够稳健。
报告全部失败和缺失run；仅成功任务平均耗时有幸存者偏差，需同时给全部运行成本和固定预算成功曲线。
有效性主要来自相对可信输入的验收，不直接证明人类需求忠实度、漏洞全无或生产认证合规。

## 8. 对照相关工作后的新颖性判断

截至2026-09-13的补充一手来源见 [生成方向相关工作](GENERATION_RELATED_WORK.md)。
固定规约生成、模型到代码、形式反馈修正、联合代码/证明规划均已有工作。
所以本阶段不声称“首次PSM+Agent”或“首次规约驱动”。可争取的贡献需由数据决定：

- 发现固定模型条件在代码生成中被遗漏/冲突落实的系统性模式；
- 给出跨来源、可独立执行的结构＋行为符合性评测；
- 在强通用Agent与传统生成器之间，找到有复现收益的混合生成边界。

若模板或解释器已覆盖并正确解决大多数目标任务，结论应是优先传统工具，LLM只用于未支持部分。
若G11不优于G01，撤回骨架机制优势；若仅降低样板语法错误，贡献收窄为工程符合性，不能夸大行为推理提升。
若PSM行为太不完整，先限定可研究的约束，不悄悄把规约生成加回来。
若只有自己构造的配置有效，不推广到真实MDA/工业应用。录用目标不能代替上述证据。
