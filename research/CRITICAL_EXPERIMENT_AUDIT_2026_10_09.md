# 义务状态修复实验：本地批判性审核

审核日期：2026-10-09。范围为本地实验设计、实现与已保存工件；没有网络检索、模型调用、Dafny 新实验或生产代码修改，也没有读取模型思考日志。本报告采用源码、冻结提示、结果 JSON 与既有报告作为一手证据。430 项测试及 2 个子测试通过是既有工程回归证据，本次没有重跑，不将其计入研究样本。

**判断：现有工作证明了一个能够保存真实失败、进行多轮修复并严格验收最终工件的探索管线；尚未证明义务状态或目标选择提高修复成功率。最紧迫的问题不是扩大调用量，而是让拟检验的机制在样本中实际生效，并明确比较究竟估计什么。** 多数边界已在现有报告中如实披露，以下“阻断”指阻断某类研究结论，不表示已有探索数据作废。

## 2. 最高优先级发现

### P0：成功前没有可保护的已证状态，核心构念未被激活

`EvidenceState.observe` 允许方法批次在全文件失败时被标为 `DISCHARGED`，但后置条件只有全文件成功且所有方法批次通过后才被标为 `DISCHARGED`；没有被定位的失败条款保持 `UNKNOWN`。这是保守记账，不是误判。见 [state.py](../generation/obligations/state.py) 第 55–68 行。

问题在于恢复题只有一个方法，而引擎在完整通过并完成最终重验后就停止；参见 [engine.py](../generation/engine.py) 第 256–273 行。六份 B/C 输入中确实没有成功前已证义务。因此这次试验没有机会展示“在修复未证部分时保留已证部分”，零 `proof_regressions` 的分母也不是有真实回退风险的证明机会。不能把它读成保护机制成功。

这个问题并非仅靠重做 96 次就能解决：现有 8 个开发题中 7 个是单方法；唯一双方法 `search_pipeline` 的契约允许删除方法间调用，已接收的四组解都走了独立扫描路线。任务明确披露这一点，见 [search_pipeline/task.json](../generation/obligations/development_tasks/search_pipeline/task.json) 第 15–24、204–206 行及中止报告“对研究问题的启示”。

**最低补救：** 先加入一小组真实全文件失败、但至少一个方法批次已通过的公共快照，用现有 CSV 证据能力即可，不必先开发 VC 图或细粒度证明缓存。所有组获得相同完整证据，比较下一轮已通过批次的保留与完整成功。若拟声称跨方法依赖调度，必须另设预先冻结的调用结构约束并明确它改变了任务定义；当前纯结果契约不支持该主张。

### P0：当前统计单位不足以估计效能，23 次事后变体不能补样本

恢复检查的泛化单位是一个开发题，不是四次运行、九个响应、十四次 Dafny 调用或二十三个源码变体。轮次依赖先前失败并受成功停止规则影响，不能当独立观测。A、B、C 的“首轮失败后成功率”还条件化于各自策略产生的失败，不能直接比较为修复因果效果。原路线图第 53–59 行正确指出了这些限制。

23 次局部干预能支持“此固定源码、固定工具链下，一个改动足以改变验证结果”或“某段证明代码可删除”；不能支持“C 因为目标提示才发现这个改动”。局部对照在观察结果后追加，适合生成假说；对其计算总体通过率或把 B 的事后可修复版本回填为成功都会改变估计对象。现有报告没有这样做。

**最低补救：** 把“任务 → 公共失败快照 → 策略运行 → 轮次”层级固定写入计划；每题多个快照和重复先在题内汇总，再按独立题/基础算法簇估计差值。不对一个簇或极少数簇给看似精确的 bootstrap 区间。`campaign.py` 第 81–106 行默认每题一个簇、仅产出描述性区间；正式分析必须提供经过审查的簇映射，不能把同题改写或相关算法自动当独立题。

### P1：四组能比较策略包，却不能把差值解释为独立的证明知识或智能调度

A 已获得完整当前源码、历史源码、真实验证输出和映射到需求的结构化诊断。B 加同一证据的状态摘要，C 再加目标；参见 [common_failure.py](../generation/obligations/common_failure.py) 第 56–79 行及 [policy.py](../generation/obligations/policy.py) 第 37–48 行。因此 C−A 是“状态摘要＋目标提示”的整体策略效应；B−A 是摘要呈现效应；C−B 是当前目标提示包的增量。它们不自动识别“新增证明事实”的收益，也不构成两因素完整析因试验。

`select_target` 优先语法类错误、再按状态、诊断优先级、最后按 ID 字典序选择；ID 是诊断内容的哈希，见 [state.py](../generation/obligations/state.py) 第 69–74、96–108 行。它没有调用依赖、预期修复收益或证明动作模型。同级候选的选择甚至可能随行位置变化而改变，因为位置参与诊断哈希。初次选中 R3 只能说明确定性消歧，不能说明识别了困难瓶颈。目标也是提示，不是强制局部编辑或防回退约束。

B/C 首轮 user 字符数为 4,500/4,646，A 为 3,426。长度变化是策略的一部分，对整体策略比较不构成自动失效；但如果要把效果归于状态语义而非额外重复、注意力或提示量，应单独控制。不能用字符差直接推断 token 差或因果损害。

**最低补救：** 在完全相同的失败快照和状态内容上，比较无目标、当前选择器目标、同优先级可选目标中的随机目标。随机规则在采样前冻结；只有至少两个合法候选的快照才能识别“选哪个”的效果。先区分“加一个目标是否有用”和“当前规则是否比任意同级目标更好”，再考虑动作级扩展。

### P1：预算公平目前是请求数与验证次数上限公平，不是等计算量或等费用

恢复协议每组最多 3 个 solver 请求、4 次验证，并对成功早停及最终重验统一计数。这是合理的等上限设计；D 只用一次请求、B/C 用三次本身不是不公平。最终成功后早停是算法效率结果，不应为追求“实际调用数一致”而给失败组追加机会。

但文件队列明确不支持采样 seed 或输出上限强制，配置禁止硬 token/费用上限，见 [exploration.py](../generation/obligations/exploration.py) 第 42–49、80–85、97–106 行。一次 solver 请求还包含加载工具选择和读入后回答两个推理阶段，见 [handoff.py](../generation/obligations/handoff.py) 第 96–102 行。恢复批次 `batch.json` 中 `total_tokens=null`、`cost_usd=null`、`output_cap_enforced=false`。所以名义 `output_tokens=4096` 不能视为实际强制预算，582,808 token 也含平台上下文。

**最低补救：** 现有入口继续称“等候选/验证上限探索”；报告 success-at-1/2/3、各组可见输入/输出及完整成本分布。要宣称等 token/费用下优越，需另开有实际强制预算的协议，不能事后按已用 token 匹配或删样本，因为用量也受策略和早停影响。排队和派发耗时应单独记录，当前 `model_seconds` 不适合称算法速度。无可强制 seed 不妨碍随机重复，但不能声称使用配对随机数或逐 token 可复现。

### P1：题池与准入尚不能支撑自然修复或一般形式验证泛化

`prepare` 对每题固定使用 `mutants[0]`，只检查参考通过、人工起点 `verification_failed`，见 [file_campaign.py](../generation/obligations/file_campaign.py) 第 129–138 行。所有 8 个开发题的 `equivalence_audit.status` 仍为 `pending`。人工明显算错的起点、纯方法体语法子集、允许完全重写的操作空间，与“修复真实模型证明失败”不是同一总体；公式或内建算子捷径还会消除原本期待的多轮路径。

这些选择可以构成有效的条件修复研究，但应将结论限定为该总体。参考通过只证明规格可满足；负对照验证失败不证明规格覆盖自然语言意图，也不证明负例一定有行为反例。`prefix_maxima` 的具体存在性契约可读且有意义，不应仅因全体审计 pending 就断言它错误；缺的是独立审查的完成证据。见 [prefix_maxima/task.json](../generation/obligations/development_tasks/prefix_maxima/task.json) 第 15–23、210–217 行。

**最低补救：** 完成契约语义、可满足性、平凡解及近重复审查；用独立于待比较策略的固定生成流程收集公共失败池。预先冻结生成预算、纳入规则和所有失败快照，不能只留下 C 擅长修的失败或只保留后来成功的题。保留人工机制探针，但与自然模型失败分层报告，已暴露的 A1/B3 只可用于开发。

### P2：可审计性强于可迁移复现性，两者需要分开表述

代码和工件哈希、唯一响应、完整 loader stdout、模型名与推理强度审计是实质性的优点；参见 [file_campaign.py](../generation/obligations/file_campaign.py) 第 106–118、148–158 行和 [handoff.py](../generation/obligations/handoff.py) 第 157–225 行。

仍有复现边界：底层模型权重不能由别名冻结；大量平台系统上下文不等同于项目 SYSTEM 提示；`validate_response` 依赖本机绝对 `session_path`；`PARENT` 及恢复控制器的会话日期目录硬编码在本地。见 `file_campaign.py` 第 27、149–150 行，`handoff.py` 第 207–215 行，`logs/file-handoff-recovery-20261007/driver.py` 第 64 行。保存源码哈希证明“当前文件一致”，不等于外部人员拿到文件后可以完整复现同一次模型采样。

**最低补救：** 提供可移植的公开消息、最终回答、候选、验证证据、工具版本和运行清单，并明确哪些完整会话证据仅能在原机器审计；不需要公开思考日志。时间、模型返回身份、环境摘要及工具能力版本应单独保存。不要将这些限制写成已发生泄漏或错误。

## 3. 合理限制与不是缺陷的事项

- **成功认定保守且恰当。** 持久化 final 文件后重新读取并全文件验证，候选验证和最终重验都占预算；`engine.py` 第 97–117、256–268 行支持这一点。失败诊断不是行为反例，UNKNOWN 不是已证，这些设计应保留。
- **共同人工起点解决了一项真实混淆。** 各组不再只修复各自选择出来的首轮失败，但它估计的是人工起点条件下的修复效果，不能替代从零生成试验。
- **跨午夜停批不是结果择优停止的证据。** 旧协议保存中断和消耗，新协议不追认旧响应，恢复检查预先固定四次且允许算法失败；现有文件与这一规则一致。不能把“有中断”直接等同于选择偏差。
- **D 是必要而合理的效率参照。** 当前 D 首轮消息与 A 完全相同且首轮成功，说明本次没有实际观察到重采样效果；不说明独立采样设计错误。
- **局部证明表达敏感性值得研究。** A1 一条断言可修复、B3 删除辅助循环可通过等结果是有效的源码级探索发现；它们尚不足以判定具体 SMT trigger 原因，也未验证模型能可靠选择这些动作。
- **430 项测试通过不该继续重复放大为研究优势。** 它支持软件回归质量，不能抵消题集、机制暴露和统计识别不足。当前最需要的不是再扩日志系统或增加架构层。

## 4. 最小可识别的下一项实验

建议先开一个独立命名的“公共快照单步修复机制试验”，不要把它并入旧 96 次矩阵，也不要先投入 4,000 次确认调用。原 A/B/C/D 矩阵仍可作为策略整体比较，但不是下面机制试验的替代品。

1. **冻结快照池。** 从独立的固定 baseline 收集真实失败，或先使用明确标记的开发机制探针；所有组拿同一源码、原始诊断和历史。收集预算、纳入规则、题目簇及失败来源在看各组结果前冻结。记录未出现失败的题，不能静默删除。机制子集至少包含“全文件失败但已有真实已通过方法批次”以及“同优先级有多个可选目标”；分别标记两个子集，不能假定每个快照都满足二者。
2. **每次只修一步。** 使用相同模型配置、一个 solver 响应、一次候选验证与成功时一次最终重验；非法答案照常失败。这样各组的前态与历史相同，避免先前轨迹差异成为目标机制解释。它估计一步转换，不能直接宣称多轮策略最优。
3. **采用最小四条件。** A 为完整原始反馈；B 为 A＋真实状态摘要；C 为 B＋当前选择器目标；R 为 B＋同优先级随机目标。B−A 测摘要；C−B 测添加当前目标；C−R 测当前规则是否优于任意同级目标。C−R 在只有一个候选时无识别力，必须单列。R 只随机目标，不能伪造真假状态。这个新机制协议可暂不加入 D：单步时 D 与 A 相同；多轮效能确认仍保留 D。
4. **先定主对比与指标。** 若研究主张是选择器收益，以 C−R 为主；若主张是状态摘要收益，以 B−A 为主，不把显著的一个事后升级为主结果。完整通过率是主质量指标；已通过方法批次保留率、真实回退/不可观测转移、目标所在方法是否被修改与候选验证成本是机制检查。编辑位置只说明遵从性，不能代替证明成功；无真实已通过批次的快照不进入保护率分母。
5. **以任务为推断单位。** 对同题快照、重复先汇总，按任务/算法簇配对；报告所有任务及不确定性。小批规模只用于确认机制能被观测和估计方差，不预设它有检出 5 个百分点差的功效。只有得到足够独立簇和方差估计后再冻结确认样本量。
6. **保留统一停止与失败规则。** 成功、非法输出、预算耗尽、协议中止和未启动分别保存；所有已消费请求保留成本。机制开发可以根据发现另开新版本，但不得回写本批，也不得根据组间胜负删除快照、扩样或更换主指标。

该方案主要复用当前 `RepairPolicy`、方法批次证据、文件交接与验收器，只需一项随机同级目标消融和明确的快照准入。动作选择、局部编辑约束、细粒度 VC 图属于后续假说；在上述机制差异尚不可观测前同时加入，会增加自由度并使因果解释更困难。

## 5. 对当前研究主张的建议表述

可以写：**“我们实现了固定规约下的保守证据账本与确定性反馈目标提示，在可审计的单题恢复检查中观察到真实多轮修复和预算耗尽失败；源码局部对照显示证明表达与辅助代码可改变可验证性。”**

目前不应写：**“义务状态提高了成功率”“依赖驱动调度解决了验证瓶颈”“保护机制避免了回退”“等计算量优于独立采样”或“已完成 96 次验证研究”。** 若下一步只复跑现有任务和相同四条件，最多加强条件修复策略包的开发测量；若目标是研究机制，就应先补上述可识别设计。
