# 预实验设计与有效性限制

问题：固定且相同的需求内容下，输入表示和验证反馈如何影响生成正确性与成本？
不研究规约自动生成，不假设 structured 更好，不主张机制新颖性。

## 因素与控制变量

三种表示：编号锚定的自然段落、逐条 checklist、简单 JSON constraints。
每个 requirement_id 映射到三种表示及固定 Dafny 验收条款；机器检查覆盖与哈希，**不证明语义等价**。
5 项演示全部 pending，正式比较前由独立人员逐条检查是否遗漏/新增边界、示例或算法提示。
冻结的公开接口和隐藏契约在全部条件中相同，模型只看到当前表示。

三种策略共用候选协议、装配器、验证器、受控诊断函数和预算实现：

- single_shot：一次生成、一次完整最终验证，测量一次性能力。
- iterative_repair：以当前方法体和受控失败信息修复，成功候选另做最终重验。
- independent_sampling：与 iterative 相同资源上限，所有生成调用相互独立；编排器仅用验证结果选取成功候选。

以 `iterative_repair - independent_sampling` 为反馈的主要预算控制比较；不能只用 iterative 对 single_shot
就宣称反馈有效。初始参考不提供给真实 Agent；所有策略均从无实现开始。
模型、输出 cap、调用/token/费用/时间/验证预算、工具链、种子计划、诊断策略均冻结。
同 task×repeat 对应同种子起点，后续候选种子按轮次递增；若供应商不支持 seed 则不发送并明确记录。
API 支持 seed 也不保证完全确定性。表示自然长度差异不填充隐藏信息，实际 token 成本本身是观察量。

## 反馈与信息隔离

所有表示条件使用同一 `controlled_v1`：类别、公开 requirement_id、方法体相对位置。
无法准确定位时为 unknown；可解释的错误数量不是逐条性质满足数。
原始验证输出、隐藏源码、其他表示、参考、单元样例不进入反馈。
schema 中的 natural_quote 是手工审计定位，不在模型消息中附带其他表示映射。
所有调用无会话继承；independent_sampling 每轮消息一致，不含前次候选/诊断/剩余时间。
模型本身没有任意工具调用权限，唯一动作是提交受限方法体；编排器负责验证。

## 验收、指标与失败保留

完整成功＝边界合法＋冻结资产未变＋最终持久化文件的完整真实 Dafny 验证成功＋预算内。
首次候选通过也要求最终工件通过；超时、unknown、解析错误、工具失败等一律不计成功。
准入阶段单独验证正确参考和至少一个已知错误实现并保存证据；没有通过准入时不调用模型。
verification_failed 可能是缺少证明或求解器能力限制，不自动等于存在语义反例。

报告任务数、重复数、逐任务成功比例、条件内首次通过/预算内成功、模型/验证调用数、token、费用、耗时和失败类型。
mock/真实模型、pending/human_reviewed 分组；成功/失败/未完成均保留。默认仅透明描述统计，
不将重复当成独立任务，不用演示矩阵计算论文显著性。API 未返回用量时 token/cost 统计为 null。
数据准入的额外验证开销与模型在线预算分开，不隐藏为免费工作；配置含全部上限。

## 当前能回答和不能回答什么

mock 的错误→参考序列可测试修复路径和诊断隔离，但它并不读取诊断进行推理。
因此 iterative 与 independent 的 mock 成功率即使相同/不同，也不是反馈作用证据。
single_shot 的 mock 失败是夹具设计，不能用来论证真实模型需要修复。

演示只有一个自建来源、五题、全部 dev；缺少人工等价性审查、非空前置条件/验收充分性独立检查和 held-out 测试集。
同一作者准备参考与验收有共同错误风险，已知 mutant 检出只是有限负对照。
受限语法、Dafny 证明难度和反馈归因 unknown 可能改变外部效度；并发/数据库/平台语义未覆盖。
未执行真实模型请求，所以无法评价真实修复能力、表示优劣或在线服务兼容性。

## 下一阶段门槛

1. 独立审阅五题的三表示等价性、映射、验收充分性与来源许可；审阅者/日期/证据填入任务审计字段并重新冻结哈希。
2. 引入多个公开来源且具有可检查固定规约的任务，按来源划分 dev/test，查近重复和训练污染风险；保留传统生成器可解决的任务作控制。
3. 先授权并运行一个真实模型 task×三表示 smoke，确认实际请求参数、响应解析、token/cost 与工具链记录。
4. 预注册同预算的修复/独立采样比较，在 dev 冻结参数后做测试集重复运行；若无稳定增益，报告负结果，不默认追加复杂模块。
